Network Address Translation (NAT) Explained

Network Address Translation (NAT) is a networking technique that modifies IP address information in packet headers as packets pass through a router or another network device.

NAT is commonly used to allow devices with private IPv4 addresses to communicate with external networks using public IPv4 addresses.

1. Why Do We Need NAT?

IPv4 provides approximately 4.3 billion possible addresses. However, the rapid growth of internet-connected devices has made globally unique IPv4 addresses scarce.

Private IPv4 addresses can be reused across different organizations and home networks. They are not directly routable across the public internet.

NAT allows many devices using private addresses to access external networks through one or more public addresses.

2. Private IPv4 Address Ranges

RFC 1918 defines three private IPv4 address ranges:

Private Range CIDR Address Count
10.0.0.0 – 10.255.255.255 /8 16,777,216
172.16.0.0 – 172.31.255.255 /12 1,048,576
192.168.0.0 – 192.168.255.255 /16 65,536

3. Types of NAT

Three commonly studied NAT approaches are:

  • Static NAT
  • Dynamic NAT
  • Port Address Translation (PAT)

Static NAT

Static NAT creates a fixed one-to-one mapping between a private IP address and a public IP address.

For example, an internal server with address 192.168.1.10 can be mapped to public address 203.0.113.10. 

configure terminal

interface gigabitEthernet 0/0
ip nat inside
exit

interface gigabitEthernet 0/1
ip nat outside
exit

ip nat inside source static 192.168.1.10 203.0.113.10

Dynamic NAT

Dynamic NAT maps private addresses to available public addresses from a configured pool.

Unlike Static NAT, the mapping is not permanently fixed to one particular public address. 

configure terminal

access-list 1 permit 192.168.1.0 0.0.0.255

ip nat pool PUBLIC_POOL 203.0.113.10 203.0.113.20 netmask 255.255.255.0

ip nat inside source list 1 pool PUBLIC_POOL

Port Address Translation (PAT)

PAT allows multiple private devices to share one public IPv4 address by using different transport-layer port numbers.

It is also commonly called NAT Overload. 

configure terminal

access-list 1 permit 192.168.1.0 0.0.0.255

interface gigabitEthernet 0/0
ip nat inside
exit

interface gigabitEthernet 0/1
ip nat outside
exit

ip nat inside source list 1 interface gigabitEthernet 0/1 overload

In this example, the router uses its outside interface address for translations and distinguishes simultaneous connections using port information.

4. Understanding NAT Terminology

Cisco NAT terminology describes addresses from the perspective of the network being translated.

Term Meaning
Inside Local Address of an inside host as it appears within the inside network, usually private.
Inside Global Address representing an inside host to the outside network.
Outside Global Address assigned to an outside host in the outside network.
Outside Local Address representing an outside host to the inside network.

5. Inside and Outside Interfaces

A NAT router identifies which interfaces face the inside network and which face the outside network. 

interface gigabitEthernet 0/0
ip nat inside

interface gigabitEthernet 0/1
ip nat outside

The actual interface names depend on the router model and network topology.

6. NAT Verification Commands

show ip nat translations

show ip nat statistics

show access-lists

show running-config

debug ip nat

Use debug commands carefully because they can generate significant output on busy devices.

7. Common NAT Troubleshooting Problems

  • Inside and outside interfaces configured incorrectly.
  • Incorrect access-list network or wildcard mask.
  • Missing default route toward the outside network.
  • Incorrect NAT pool configuration.
  • Missing overload keyword when PAT is intended.
  • Incorrect IP addressing or subnet masks.
  • Traffic not reaching the router for translation.

8. Practical Packet Tracer Lab

Build a small network containing:

  • One Cisco router
  • One switch
  • Two internal PCs
  • One simulated external network or server

Configure the following:

  1. Assign private IPv4 addresses to internal PCs.
  2. Configure the router's inside and outside interfaces.
  3. Configure PAT using the outside interface address.
  4. Configure a suitable default route.
  5. Test connectivity to the external server.
  6. Inspect the NAT translation table.

Conclusion

NAT plays an important role in IPv4 networks by translating addresses between inside and outside networks. Static NAT, Dynamic NAT and PAT serve different requirements.

Understanding NAT configuration and verification is an important skill for network engineers and administrators.
