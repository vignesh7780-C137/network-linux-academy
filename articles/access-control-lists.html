Access Control Lists (ACLs) Explained

Access Control Lists (ACLs) are sets of rules used by network devices to permit or deny traffic based on specified conditions. They are commonly configured on routers and Layer 3 switches.

ACLs help administrators control network traffic, restrict unauthorized communication and implement basic traffic filtering.

1. Why Are ACLs Important?

Consider an organization with three departments:

  • Administration: 192.168.10.0/24
  • Engineering: 192.168.20.0/24
  • Finance: 192.168.30.0/24

Suppose the organization wants to prevent Engineering computers from accessing Finance computers while allowing other communication.

An ACL can inspect packet information and decide whether the traffic should be permitted or denied.

2. How Do ACLs Work?

ACL entries are evaluated from top to bottom. The device processes the first matching entry and applies its action.

There are two common actions:

  • Permit: Allow matching traffic.
  • Deny: Block matching traffic.
Important: Cisco ACLs have an implicit deny-all rule at the end. Traffic that does not match an earlier permit statement is denied.

3. Types of ACLs

Standard ACL

Standard ACLs filter traffic based only on the source IPv4 address.

Example:

access-list 10 permit 192.168.10.0 0.0.0.255
access-list 10 deny any

This permits traffic from the 192.168.10.0/24 source network and denies other sources.

Extended ACL

Extended ACLs can filter traffic using several fields, including:

  • Source IP address
  • Destination IP address
  • IP protocol
  • TCP or UDP port numbers

Example:

access-list 101 permit tcp
192.168.10.0 0.0.0.255
192.168.20.0 0.0.0.255 eq 80

This example permits matching TCP traffic from the 192.168.10.0/24 network to destination port 80 in the 192.168.20.0/24 network.

4. Numbered ACLs vs Named ACLs

ACLs can be configured using numeric identifiers or descriptive names.

Numbered Standard ACL

access-list 10 permit 192.168.10.0 0.0.0.255

Named Standard ACL

ip access-list standard ADMIN_ACCESS
permit 192.168.10.0 0.0.0.255
deny any
exit

Named Extended ACL

ip access-list extended BLOCK_FINANCE
deny ip 192.168.20.0 0.0.0.255 192.168.30.0 0.0.0.255
permit ip any any
exit

5. Understanding Wildcard Masks

Wildcard masks tell an ACL which bits of an IPv4 address should be matched.

A wildcard mask is the inverse of a subnet mask.

Subnet Mask Wildcard Mask
255.255.255.0 0.0.0.255
255.255.0.0 0.0.255.255
255.255.255.255 0.0.0.0

For example, 192.168.10.0 0.0.0.255 matches addresses in the 192.168.10.0/24 network.

6. Inbound vs Outbound ACLs

Inbound ACL

An inbound ACL examines packets as they enter a router interface, before the router makes its forwarding decision.

Outbound ACL

An outbound ACL examines packets as they leave a router interface, after the routing decision.

7. Applying an ACL to an Interface

Example extended ACL:

configure terminal

ip access-list extended BLOCK_FINANCE
deny ip 192.168.20.0 0.0.0.255 192.168.30.0 0.0.0.255
permit ip any any
exit

Apply the ACL inbound on an interface:

interface gigabitEthernet 0/0
ip access-group BLOCK_FINANCE in
exit

The interface name and direction must be chosen according to the actual network topology.

8. Verification Commands

show access-lists

show ip access-lists

show ip interface

show running-config

9. Common ACL Troubleshooting Problems

  • Incorrect source or destination IP address.
  • Incorrect wildcard mask.
  • ACL applied to the wrong interface.
  • Incorrect inbound or outbound direction.
  • Missing permit statement due to implicit deny.
  • ACL entries arranged in the wrong order.
  • Incorrect protocol or port number.

10. Practical Lab Challenge

Build a Packet Tracer network with:

  • One router
  • Three switches or VLANs
  • Three different IPv4 networks
  • At least one PC in each network

Configure these requirements:

  1. Allow Administration to communicate with all networks.
  2. Prevent Engineering from accessing Finance.
  3. Allow Engineering to access Administration.
  4. Verify the results using ping and ACL counters.

Conclusion

ACLs are essential tools for controlling network traffic. Understanding standard and extended ACLs, wildcard masks, rule ordering and interface direction helps network administrators implement effective traffic filtering.
