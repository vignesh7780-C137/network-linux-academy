EtherChannel Explained: Link Aggregation, LACP and PAgP

Enterprise networks often need more bandwidth and redundancy between switches. EtherChannel combines multiple physical Ethernet links into one logical connection to help achieve these goals.

1. What Is EtherChannel?

EtherChannel is a Cisco technology that groups multiple physical Ethernet links into a single logical link called a port-channel.

Instead of treating each cable as an independent connection, switches manage the bundled links as one logical interface.

2. Why Do We Need EtherChannel?

  • Increased aggregate bandwidth: Multiple links contribute capacity to the bundle.
  • Redundancy: Traffic can continue over remaining member links if one link fails, provided the channel remains operational.
  • Load distribution: Traffic can be distributed across member links using a hashing algorithm.
  • Simplified STP operation: STP normally sees a correctly formed EtherChannel as one logical link.

3. How Does EtherChannel Work?

Consider two switches connected using four physical Gigabit Ethernet cables.

These four links can be bundled into one logical Port-Channel interface. The switches distribute traffic across available member links.

A single traffic flow is generally mapped to one physical member link at a time. EtherChannel does not normally split every individual frame across all links.

4. EtherChannel Protocols

LACP

Link Aggregation Control Protocol (LACP) is an industry-standard link aggregation protocol defined by IEEE 802.1AX, historically associated with IEEE 802.3ad.

LACP dynamically negotiates and maintains compatible link aggregation between devices.

PAgP

Port Aggregation Protocol (PAgP) is a Cisco-proprietary protocol used to negotiate EtherChannel formation.

Comparison

Feature LACP PAgP
Standard IEEE 802.1AX Cisco proprietary
Active mode Actively sends LACP messages Not applicable
Passive mode Waits for LACP messages Not applicable
Desirable mode Not applicable Actively negotiates
Auto mode Not applicable Waits for PAgP messages

5. LACP Modes

  • Active: Initiates LACP negotiation.
  • Passive: Responds to LACP negotiation but does not initiate it.

An active side can form a channel with a passive side. Two passive sides will not initiate negotiation.

6. PAgP Modes

  • Desirable: Actively negotiates EtherChannel.
  • Auto: Waits for another device to initiate negotiation.

A desirable side can form a channel with an auto side. Two auto sides will not initiate negotiation.

7. EtherChannel Configuration Requirements

Physical interfaces in the same EtherChannel must have compatible configurations.

  • Compatible interface speeds and duplex settings.
  • Same access VLAN when configured as access ports.
  • Matching trunk configuration when configured as trunks.
  • Compatible allowed VLAN and native VLAN settings.
  • Same channel protocol and compatible negotiation modes.
  • Compatible Layer 2 or Layer 3 configuration.

8. Cisco EtherChannel Configuration Using LACP

Example: two switches have two physical connections, GigabitEthernet 0/1 and 0/2. We will bundle them into Port-Channel 1.

Switch 1

enable
configure terminal

interface range gigabitEthernet 0/1 - 2
 switchport mode trunk
 channel-group 1 mode active
 no shutdown

interface port-channel 1
 switchport mode trunk

end
write memory

Switch 2

enable
configure terminal

interface range gigabitEthernet 0/1 - 2
 switchport mode trunk
 channel-group 1 mode active
 no shutdown

interface port-channel 1
 switchport mode trunk

end
write memory

Both switches use LACP active mode. Ensure that both ends have compatible trunk and channel settings.

9. Verification Commands

show etherchannel summary

show etherchannel detail

show interfaces port-channel 1

show lacp neighbor

show interfaces trunk

Use these commands to confirm that the port-channel is formed, member interfaces are bundled, and LACP neighbors are detected.

10. Key Takeaways

  • EtherChannel combines multiple physical links into one logical link.
  • LACP is the standards-based negotiation protocol; PAgP is Cisco proprietary.
  • Member interfaces must have compatible configurations.
  • Use verification commands to confirm channel and member-link status.

Conclusion

EtherChannel improves aggregate link capacity and provides link-level redundancy between network devices. Understanding its negotiation protocols, configuration requirements and verification commands is important when designing and troubleshooting switched networks.
