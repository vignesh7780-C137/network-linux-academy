1. What Is an IPv4 Address?

An IPv4 address (Internet Protocol version 4 address) is a numerical identifier assigned to a network interface. It is used by devices to identify the source and destination of packets when communicating across an IP network.

Think of an IP address as a network-level address that helps routers determine where packets should be delivered. Your laptop, smartphone, server, and router interfaces may all use IP addresses to communicate.

IPv4 is one of the most widely deployed versions of the Internet Protocol. It uses a 32-bit addressing system, which provides a theoretical total of 232 possible address values.

Example IPv4 address 192.168.1.10

This is an example of a private IPv4 address commonly used inside home and office networks.

2. The Structure of an IPv4 Address

An IPv4 address contains 32 bits. These bits are divided into four groups of eight bits each. Each eight-bit group is called an octet.

In normal networking configurations, IPv4 addresses are written in dotted-decimal notation. The four decimal numbers are separated by periods.

192Octet 1
168Octet 2
1Octet 3
10Octet 4

192 . 168 . 1 . 10

4 octets × 8 bits = 32 bits

Each octet can represent a decimal value from 0 to 255. This is because eight binary bits can represent 256 different combinations, ranging from 00000000 to 11111111.

Total length32 bits
Number of octets4

3. Understanding Binary and Octets

Computers process information using binary values: 0 and 1. To understand IPv4 addressing and subnetting, it is useful to understand how eight binary bits represent a decimal number.

Each position in an eight-bit octet has a place value. From left to right, these values are 128, 64, 32, 16, 8, 4, 2, and 1.

Bit position 1234 5678
Place value 128643216 8421
Binary digit 1100 0000

In this example, the binary number 11000000 is converted into decimal by adding the place values where the bit is 1:

128 + 64 = 192

Therefore, the binary octet 11000000 represents the decimal number 192.

Complete IPv4 binary example

Consider the IPv4 address 192.168.1.10:

1000001010

When combined, these four octets form the complete 32-bit IPv4 address.

4. Network Portion and Host Portion

An IPv4 address is logically divided into two parts: the network portion and the host portion.

  • Network portion: Identifies the IP network to which an address belongs.
  • Host portion: Identifies an interface within that network.

The subnet mask or prefix length determines where the network portion ends and the host portion begins.

Important concept

The same IPv4 address can be interpreted differently depending on its subnet mask. An IP address alone does not tell you the complete network boundary.

For example:

IP address and subnet mask 192.168.1.10 / 255.255.255.0

With a /24 prefix, the first 24 bits identify the network. The remaining 8 bits identify the host portion.

  • Network address: 192.168.1.0
  • Example host address: 192.168.1.10
  • Broadcast address: 192.168.1.255

5. What Is a Subnet Mask?

A subnet mask is a 32-bit value used to distinguish the network bits from the host bits in an IPv4 address.

In binary, the network portion of a conventional subnet mask consists of consecutive 1s, followed by consecutive 0s for the host portion.

The traditional usable-host figures assume an ordinary IPv4 subnet where the network and broadcast addresses are reserved. Special cases such as /31 point-to-point links and /32 host routes have different uses.

How does a subnet mask work?

Consider the address 192.168.1.10 with the subnet mask 255.255.255.0.

IP address

11000000.10101000.00000001.00001010

Subnet mask

11111111.11111111.11111111.00000000

Network address

11000000.10101000.00000001.00000000

The network address is calculated by performing a bitwise AND operation between the IP address and the subnet mask. This operation retains the bits that are 1 in both values.

6. CIDR Notation Explained

CIDR stands for Classless Inter-Domain Routing. It provides a flexible way to represent IPv4 network prefixes. Instead of relying on the old fixed address classes, CIDR specifies exactly how many leading bits belong to the network.

CIDR notation places a forward slash after an IPv4 address, followed by a number between 0 and 32.

CIDR example 192.168.1.10/24

The number /24 means that the first 24 bits are the network prefix. The remaining 8 bits are available for the host portion.

Understanding prefix lengths

  • /8: 8 network bits and 24 host bits.
  • /16: 16 network bits and 16 host bits.
  • /24: 24 network bits and 8 host bits.
  • /26: 26 network bits and 6 host bits.
  • /30: 30 network bits and 2 host bits.

A larger prefix length means more bits are used for the network portion and fewer bits remain for host addresses.

CIDR is important in modern routing because it supports flexible address allocation and route aggregation. It replaced the limitations of the old class-based approach.

7. Private vs. Public IP Addresses

IPv4 addresses are commonly discussed as private or public addresses. The difference is important when designing home, office, and enterprise networks.

Private IPv4 addresses

Private IPv4 addresses are reserved for use inside private networks. They are not globally reachable as ordinary public Internet destinations.

The three private IPv4 ranges defined by RFC 1918 are:

Private range CIDR Number of addresses Common description
10.0.0.0 – 10.255.255.255 10.0.0.0/8 16,777,216 Large private range
172.16.0.0 – 172.31.255.255 172.16.0.0/12 1,048,576 Medium private range
192.168.0.0 – 192.168.255.255 192.168.0.0/16 65,536 Common home and small-office range

For example, a home router may assign addresses such as 192.168.1.10 and 192.168.1.11 to devices on the local network.

Public IPv4 addresses

Public IPv4 addresses are globally unique addresses that can be routed across the public Internet, subject to routing policies and other network controls.

An Internet Service Provider (ISP) may assign a public IPv4 address to a customer's router. The router can then use Network Address Translation (NAT) to allow multiple private network devices to share that public address.

Remember

Private addressing and NAT are related, but they are not the same thing. Private addresses identify devices inside a private network; NAT translates addresses between addressing domains.

8. Special IPv4 Addresses

Not every IPv4 address is available for ordinary host assignment. Some address blocks have specific purposes.

Address or range Purpose
127.0.0.0/8 Loopback addresses; 127.0.0.1 is commonly used to refer to the local host.
169.254.0.0/16 IPv4 link-local addressing.
0.0.0.0 Unspecified address in contexts where no specific address is available.
255.255.255.255 Limited broadcast address.
224.0.0.0/4 IPv4 multicast address space.
100.64.0.0/10 Shared address space, commonly associated with carrier-grade NAT.
192.0.2.0/24 Documentation and examples (TEST-NET-1).
198.51.100.0/24 Documentation and examples (TEST-NET-2).
203.0.113.0/24 Documentation and examples (TEST-NET-3).

The three TEST-NET ranges are useful in tutorials and documentation because they are reserved for examples. They should not be treated as ordinary public host addresses.

9. Historical IPv4 Address Classes

Early IPv4 addressing used a class-based system. The address space was divided into Classes A, B, C, D, and E.

This approach is now historical for normal network allocation. Modern networks use CIDR and explicit prefix lengths instead. However, understanding the classes can help when reading older networking material and preparing for technical interviews.

Class Historical first-octet range Historical default mask Original general purpose
A1–126255.0.0.0 (/8)Large networks

The range 127.0.0.0/8 is reserved for loopback, so it is not an ordinary Class A network assignment. The historical class ranges are not a substitute for checking the actual prefix of an address.

Important for modern networking

Do not assume that an address beginning with 192 automatically uses a /24 mask, or that an address beginning with 10 automatically uses /8. The configured prefix determines the network boundary.

10. Practical Subnetting Example

Let's calculate the network details for the following IPv4 address:

Given address 192.168.10.34/27

Step 1: Identify the subnet mask

A /27 prefix means 27 bits are used for the network portion. The corresponding subnet mask is:

255.255.255.224

Step 2: Calculate the block size

The interesting octet is the fourth octet because the subnet mask changes there.

Block size = 256 − 224

Block size = 32

The subnet ranges in the last octet therefore increase in blocks of 32:

0–31 32–63 64–95 96–127 128–159 160–191 192–223 224–255

Step 3: Find the network address

The host address ends in 34. Since 34 falls inside the range 32–63, the network address is:

192.168.10.32

Step 4: Find the broadcast address

The last address in the range 32–63 is the broadcast address:

192.168.10.63

Step 5: Find the usable host range

In this ordinary /27 subnet, the network address and broadcast address are not assigned to individual hosts. The usable host range is:

192.168.10.33 – 192.168.10.62

Step 6: Calculate the number of usable hosts

There are 5 host bits because 32 − 27 = 5. The total number of addresses is 25 = 32. Subtract the network and broadcast addresses:

32 − 2 = 30 usable host addresses

Final result

Given IP address192.168.10.34/27
Subnet mask255.255.255.224
Network address192.168.10.32
First usable host192.168.10.33
Last usable host192.168.10.62
Broadcast address192.168.10.63
Total addresses32
Usable host addresses30

This is a foundational subnetting calculation. With practice, you will be able to perform these calculations quickly when configuring routers, switches, VLANs, and enterprise networks.

How to Check Whether Two Devices Are in the Same Subnet

Two devices can communicate directly at Layer 2 only when they are on the same local network segment or VLAN and their IP configuration places them in the same IP subnet. To check the IP subnet, apply the same subnet mask to each IP address and compare the resulting network addresses.

Example: both devices use /27

DeviceIP addressNetwork address
PC-A192.168.10.34/27192.168.10.32
PC-B192.168.10.62/27192.168.10.32
PC-C192.168.10.65/27192.168.10.64

PC-A and PC-B calculate to the same network address, 192.168.10.32/27. PC-C belongs to 192.168.10.64/27, so it is in a different subnet. Communication between different subnets requires Layer 3 routing.

Important distinction

Sharing an IP subnet does not guarantee connectivity. The devices must also have working link connectivity, compatible VLAN placement, valid host configuration, and no filtering that blocks the traffic.

Quick subnetting practice

Try calculating the network address, broadcast address, usable range, and number of usable hosts for 192.168.5.77/26.

Reveal the worked answer

A /26 mask is 255.255.255.192. The block size is 256 − 192 = 64, so the fourth-octet ranges are 0–63, 64–127, 128–191, and 192–255. Since 77 falls in 64–127:

  • Network address: 192.168.5.64
  • First usable host: 192.168.5.65
  • Last usable host: 192.168.5.126
  • Broadcast address: 192.168.5.127
  • Usable host addresses: 26 − 2 = 62

11. How to View Your IPv4 Address

You can inspect the IPv4 configuration of your own computer using built-in command-line tools.

On Windows

Open Command Prompt and run:

ipconfig

To see more detailed network configuration information, run:

ipconfig /all

Look for the active network adapter and its IPv4 Address, Subnet Mask, and Default Gateway fields.

On Linux

Open a terminal and run:

ip address

You can also use the shorter form:

ip -4 addr

These commands display IPv4 addresses assigned to the machine's network interfaces. You may see multiple interfaces, including loopback, Ethernet, and Wi-Fi.

12. Common IPv4 Addressing Mistakes

  1. Confusing an IP address with a subnet mask. An IP address identifies an interface, while the prefix or subnet mask defines the network boundary.
  2. Assuming every 192.168 address uses /24. The prefix can vary. Always check the configured mask.
  3. Confusing private addresses with public addresses. Private addresses are intended for internal networks and are not globally reachable as ordinary Internet destinations.
  4. Forgetting the network and broadcast addresses. In a conventional IPv4 subnet, these are not assigned to ordinary hosts.
  5. Thinking address classes are how modern networks are allocated. Modern IPv4 networks use classless prefix notation (CIDR).
  6. Ignoring the subnet mask during troubleshooting. Two devices with apparently similar IP addresses may still be configured for different subnets.

13. Frequently Asked Questions

1. How many bits are in an IPv4 address?

An IPv4 address contains 32 bits, divided into four octets of 8 bits each.

2. Why does an IPv4 octet range from 0 to 255?

An octet contains eight bits. Eight bits provide 28, or 256, possible values. Those values range from 0 through 255.

3. What is the difference between IPv4 and IPv6?

IPv4 uses 32-bit addresses, while IPv6 uses 128-bit addresses. IPv6 provides a vastly larger address space and a different addressing format.

4. What does /24 mean in an IP address?

It means the first 24 bits form the network prefix. The remaining 8 bits form the host portion. Its subnet mask is 255.255.255.0.

5. Is 192.168.1.1 a public or private IP address?

It is a private IPv4 address because it belongs to the RFC 1918 range 192.168.0.0/16.

6. What is the purpose of a default gateway?

A default gateway is the router or next-hop device a host uses to send packets to destinations outside its local subnet, when no more specific route applies.

7. Are IPv4 address classes still used?

Class A, B, and C are historical concepts. Modern address allocation and routing use CIDR prefixes. Class D and E terminology may still appear when discussing multicast and reserved address space.

14. Conclusion

IPv4 addressing is one of the most important foundations of computer networking. Understanding its 32-bit structure, octets, network and host portions, subnet masks, and CIDR notation will make it easier to understand routing and network design.

The best way to strengthen your understanding is to practise reading IP configurations and calculating subnets. Try configuring different IPv4 addresses and subnet masks in Cisco Packet Tracer, then test connectivity between devices.
