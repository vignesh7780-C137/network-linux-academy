DNS: Domain Name System Explained

DNS translates human-readable domain names into IP addresses, allowing computers to locate websites and network services.

Category: Networking Fundamentals

Reading time: 12 minutes

1. What is DNS?

DNS stands for Domain Name System. It is a distributed, hierarchical naming system that translates domain names into information such as IP addresses.

For example:

Domain Name: example.com
IPv4 Address: 93.184.216.34

Instead of remembering numerical IP addresses, users can access services using memorable domain names.

2. Why is DNS Necessary?

Computers communicate using IP addresses. However, remembering the addresses of every website and server would be difficult.

DNS provides:

  • Domain name resolution.
  • Distributed naming management.
  • Flexible IP address changes.
  • Service discovery through DNS records.
  • Scalable network communication.

3. How DNS Resolution Works

DNS resolution is the process of finding information associated with a domain name.

Consider a user accessing example.com:

  1. Client request: The browser needs the IP address of example.com.
  2. Local cache: The operating system checks available DNS caches.
  3. Recursive resolver: The request is sent to a DNS resolver if no cached answer is available.
  4. Root server: The resolver discovers the appropriate top-level domain servers.
  5. TLD server: The resolver receives a referral to the domain's authoritative DNS server.
  6. Authoritative server: The requested DNS record is returned.
  7. Response: The resolver sends the answer back to the client.

DNS Resolution Flow

       Client Computer
              |
              | DNS Query
              v
      Recursive Resolver
              |
              v
         Root Server
              |
              v
          TLD Server
              |
              v
    Authoritative Server
              |
              | DNS Answer
              v
      Recursive Resolver
              |
              v
       Client Computer
              |
              v
        Website Access

4. DNS Hierarchy

DNS follows a hierarchical structure that organizes domain names into different levels.

Root Domain

The root domain is the highest level of the DNS hierarchy. It is represented by a dot (.).

Top-Level Domain (TLD)

TLDs are located directly below the root. Examples include:

  • .com
  • .org
  • .net
  • .edu
  • .in

Second-Level Domain

This is the registered domain name under a TLD. For example, in example.com, example is the second-level domain.

Subdomain

A subdomain is located beneath another domain. Examples include: 

www.example.com
mail.example.com
blog.example.com

5. Types of DNS Queries

Recursive Query

In a recursive query, the client expects the DNS resolver to provide a final answer or an error rather than a referral to another DNS server.

Iterative Query

In an iterative query, a DNS server returns the best available answer or a referral to another DNS server. The resolver continues the lookup.

6. Common DNS Record Types

DNS records contain information about domain names and the services associated with them.

Record Purpose Example
A Maps a hostname to an IPv4 address. 192.0.2.10
AAAA Maps a hostname to an IPv6 address. 2001:db8::10
CNAME Creates an alias pointing to another domain name. www.example.com
MX Identifies mail servers for a domain. mail.example.com
NS Identifies authoritative name servers. ns1.example.com
PTR Provides reverse DNS information. Reverse hostname lookup
TXT Stores text information for verification and email security. SPF information
SOA Contains administrative information about a DNS zone. Zone information

7. DNS Port Numbers: TCP and UDP

DNS commonly uses port 53 over both UDP and TCP.

UDP Port 53

UDP is commonly used for standard DNS queries because it has low communication overhead.

TCP Port 53

TCP is used for DNS zone transfers and responses where TCP is required. DNS can also use TCP for ordinary queries.

8. DNS Caching and TTL

DNS caching temporarily stores DNS responses so that repeated lookups can be answered more efficiently.

What is TTL?

TTL stands for Time To Live. It specifies how long a DNS record may remain cached before it needs to be refreshed. 

Domain: example.com
Record: A
TTL: 3600 seconds

3600 seconds = 1 hour

Caching reduces unnecessary DNS queries and improves lookup efficiency.

9. Practical Linux DNS Commands

Linux provides several command-line utilities for DNS lookups and troubleshooting.

nslookup

Used to query DNS information.

nslookup example.com

dig

A flexible DNS lookup utility that provides detailed response information. 

dig example.com

Query specific record types:

dig example.com MX
dig example.com NS
dig example.com AAAA

host

A simple DNS lookup utility.

host example.com

Check DNS Configuration

cat /etc/resolv.conf

This file commonly displays DNS resolver configuration on Linux systems, although modern distributions may manage DNS through other services.

10. DNS Troubleshooting Scenarios

Problem 1: Website does not resolve

Possible causes:

  • Incorrect DNS server configuration.
  • DNS server unavailable.
  • Incorrect domain name.
  • Missing or incorrect DNS record.

Useful commands:

nslookup example.com
dig example.com

Problem 2: DNS Server is Unreachable

Check network connectivity and verify the configured DNS resolver. 

ip addr
ip route
ping 8.8.8.8

Problem 3: DNS Returns an Incorrect Address

Inspect the DNS response and check for stale cached information or incorrect authoritative records. 

dig example.com
dig example.com @8.8.8.8

11. DNS Security

DNS is essential to internet communication, but it can be targeted by several types of attacks.

  • DNS Spoofing: Providing false DNS information to redirect users.
  • DNS Cache Poisoning: Injecting incorrect records into a DNS cache.
  • DNS Amplification: Abusing DNS responses in reflection-based denial-of-service attacks.
  • DNS Tunneling: Carrying data through DNS queries and responses in ways that may bypass normal network controls.

DNSSEC

DNSSEC uses cryptographic signatures to help verify the authenticity and integrity of DNS data.

12. Frequently Asked Questions

Is DNS a Layer 7 or Layer 4 protocol?

DNS is an application-layer protocol. It commonly uses UDP or TCP at the transport layer.

What is the default DNS port?

DNS commonly uses port 53 over both UDP and TCP.

What is the difference between DNS and DHCP?

DNS resolves domain names into DNS records. DHCP automatically provides network configuration information to clients, including IP addresses and DNS server addresses.

Can DNS work without the internet?

Yes. DNS can operate inside private networks using internal DNS servers and private namespaces.

What is the difference between a recursive resolver and an authoritative DNS server?

A recursive resolver performs lookups on behalf of clients. An authoritative DNS server provides the official DNS records for the zones it serves.

13. Conclusion

DNS is one of the fundamental services that makes modern networking possible. It translates domain names into useful network information and supports communication between applications and servers.

For networking engineers and Linux administrators, understanding DNS resolution, record types, caching and troubleshooting commands is essential.
