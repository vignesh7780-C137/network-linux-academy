Spanning Tree Protocol (STP) Explained

Redundant connections are important in enterprise networks. They provide alternative paths when a link fails. However, redundant Layer 2 connections can also create switching loops. Spanning Tree Protocol (STP) prevents these loops.

1. What Is STP?

Spanning Tree Protocol is a Layer 2 protocol that prevents loops in Ethernet switched networks by creating a loop-free logical topology.

STP identifies redundant paths and places selected ports into a non-forwarding state. If an active path fails, STP can recalculate the topology and activate an alternative.

2. Why Do Switching Loops Occur?

Consider three switches connected in a triangle. Multiple Layer 2 paths exist between them.

Ethernet frames do not normally contain a Layer 2 time-to-live field. Broadcast and unknown-unicast frames can therefore circulate repeatedly when a loop exists.

Problems Caused by Switching Loops

  • Broadcast storms: Broadcast frames circulate repeatedly and consume network bandwidth.
  • MAC address table instability: Switches may repeatedly learn the same source MAC address on different ports.
  • Duplicate frames: Devices may receive multiple copies of the same frame.
  • Network congestion: Excessive traffic can make the network unreliable.

3. How Does STP Work?

STP exchanges Bridge Protocol Data Units (BPDUs) between switches. These messages help switches determine the loop-free topology.

The basic process is:

  1. Switches exchange BPDUs.
  2. They elect a root bridge.
  3. They calculate the best paths toward the root bridge.
  4. They select root and designated ports.
  5. Redundant paths are prevented from forwarding traffic.

4. What Is the Root Bridge?

The root bridge is the central reference point for STP path calculations. Other switches determine their best paths toward this switch.

STP elects the switch with the lowest Bridge ID as the root bridge.

Understanding Bridge ID

The Bridge ID includes a bridge priority value and a MAC address. Extended System ID information is also used in modern implementations.

If two switches have the same effective priority, the lower MAC address wins the election.

5. STP Port Roles

Root Port

On a non-root switch, the root port is the port that provides the best path toward the root bridge. A non-root switch has one root port per spanning-tree instance.

Designated Port

A designated port is selected for a network segment to forward traffic toward the spanning-tree topology. The root bridge's active ports are designated ports.

Alternate Port

An alternate port provides an alternative path toward the root bridge. In classic STP it remains non-forwarding; in RSTP it can rapidly become a forwarding path when needed.

6. STP Port States

State Purpose
Blocking Does not forward ordinary user frames or learn MAC addresses.
Listening Processes BPDUs while preparing to participate in forwarding.
Learning Learns MAC addresses but does not forward ordinary user frames.
Forwarding Forwards frames and learns MAC addresses.
Disabled Not participating in STP because the interface is disabled or unavailable.

These are the traditional 802.1D STP states. RSTP uses a different state model: discarding, learning and forwarding.

7. STP Timers

Timer Traditional default Purpose
Hello Time 2 seconds Interval between configuration BPDUs.
Forward Delay 15 seconds Duration of the listening and learning stages.
Max Age 20 seconds How long configuration information remains valid without a refresh.

8. What Is RSTP?

Rapid Spanning Tree Protocol (RSTP), standardized as IEEE 802.1w and later incorporated into IEEE 802.1Q, improves convergence compared with traditional STP.

RSTP introduces additional port roles and mechanisms that can allow faster recovery after topology changes.

STP vs RSTP

Feature STP RSTP
Standard 802.1D 802.1w
Convergence Generally slower Generally faster
Port roles Root and designated, with non-designated ports Root, designated, alternate and backup
Port states Five traditional states Discarding, learning and forwarding

9. Cisco STP Configuration

On supported Cisco switches, you can configure Rapid PVST+ to run a separate spanning-tree instance for each VLAN.

Enable Rapid PVST+

enable
configure terminal

spanning-tree mode rapid-pvst

end

Configure a Switch as Root Bridge

configure terminal

spanning-tree vlan 10 root primary

end

This Cisco command adjusts the priority to make the switch the preferred root bridge for VLAN 10, subject to the platform's supported configuration.

Verify STP

show spanning-tree

show spanning-tree vlan 10

show spanning-tree root

show spanning-tree summary

10. Important STP Security Features

PortFast

PortFast allows an appropriate edge port to transition quickly to forwarding. Use it on ports connected to end devices, not ordinary switch-to-switch links.

BPDU Guard

BPDU Guard can place a PortFast-enabled interface into an error-disabled state if it receives a BPDU. This helps protect the spanning-tree topology from unexpected switches connected to edge ports. 

configure terminal

interface fastEthernet 0/1
 spanning-tree portfast
 spanning-tree bpduguard enable

end

11. Practical Packet Tracer Lab

Create a topology using three switches connected in a triangle.

  1. Connect Switch 1 to Switch 2.
  2. Connect Switch 2 to Switch 3.
  3. Connect Switch 3 back to Switch 1.
  4. Connect a PC to each switch.
  5. Configure the switches and verify STP.
  6. Identify the root bridge.
  7. Find the root ports, designated ports and alternate or blocking path.
  8. Disconnect one active link and observe the topology change.

12. Frequently Asked Questions

Does STP work at Layer 2?

Yes. STP operates at the data link layer.

Why is a root bridge needed?

It provides a common reference point for switches to calculate their loop-free paths.

Does STP remove redundant cables?

No. It logically prevents selected redundant paths from forwarding traffic while retaining them for potential recovery.

Conclusion

STP is essential for reliable Layer 2 networks. Understanding root bridge election, port roles, port states and RSTP helps network administrators design and troubleshoot redundant switched networks.
