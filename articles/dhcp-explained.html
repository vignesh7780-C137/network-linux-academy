1. What Is DHCP?

DHCP stands for Dynamic Host Configuration Protocol. It is a network protocol that automatically provides IP configuration information to devices on an IP network.

When a computer connects to a network, it needs appropriate IP configuration to communicate with other devices. This information can be configured manually or assigned automatically by a DHCP server.

Simple definition: DHCP automatically assigns network configuration information to devices, reducing the need for administrators to configure every device manually.

Example

Imagine connecting your laptop to your home Wi-Fi. You normally do not have to manually enter an IP address, subnet mask, gateway, and DNS server.

Your router or another DHCP server can provide those settings automatically.

Example DHCP configuration received by a laptop

IP Address 192.168.1.105
Subnet Mask 255.255.255.0
Default Gateway 192.168.1.1
DNS Server 192.168.1.1

2. Why Do We Need DHCP?

Automatic IP configuration

DHCP reduces manual configuration by automatically providing IP addresses and other network settings.

Centralized administration

Administrators can manage address pools and network configuration from a central DHCP server instead of configuring each client separately.

Reduced configuration errors

Centralized assignment helps reduce mistakes such as assigning the same static IP address to multiple devices.

Efficient address utilization

DHCP leases allow addresses to be reused when devices no longer need them, subject to the server's lease and reservation policies.

Scalability

DHCP is especially useful in offices, campuses, data centers, and large networks containing many client devices.

3. How Does DHCP Work?

A DHCP client communicates with a DHCP server to obtain its network configuration. The initial discovery normally uses broadcast communication because the client may not yet have an assigned IP address or know the server's address.

For IPv4 DHCP, the process commonly uses four messages: Discover, Offer, Request, and Acknowledgment.

These four messages are commonly remembered using the abbreviation DORA.

4. Understanding the DORA Process

DORA represents the four main messages used in the initial DHCP address allocation process.

01

Discover

The client broadcasts a DHCP Discover message to locate available DHCP servers.

DHCPDISCOVER
↓
02

Offer

A DHCP server responds with a DHCP Offer containing proposed IP configuration information.

DHCPOFFER
↓
03

Request

The client broadcasts a DHCP Request indicating which offered address and server it wants to use.

DHCPREQUEST
↓
04

Acknowledgment

The selected DHCP server sends a DHCP ACK, confirming the configuration lease.

DHCPACK

Step-by-step example

Suppose a laptop joins a network where the DHCP server manages the address range 192.168.1.100 through 192.168.1.200.

  1. The laptop sends DHCP Discover to find a server.
  2. The server offers 192.168.1.105.
  3. The laptop requests 192.168.1.105.
  4. The server confirms the lease with DHCP ACK.

The laptop can now configure its interface using the assigned network settings.

Important: DORA describes the common initial allocation sequence. DHCP also supports other message types and different renewal and rebinding procedures.

5. Main DHCP Components

DHCP Client

A device that requests network configuration from a DHCP server. Examples include laptops, smartphones, printers, and servers.

DHCP Server

A system that manages IP address allocation and provides configuration information to clients.

DHCP Scope or Address Pool

A configured range of IP addresses that a DHCP server can assign to clients on a particular network.

DHCP Reservation

A configuration that associates a particular client identifier, commonly its MAC address, with a specific IP address.

DHCP Relay Agent

A network device that forwards DHCP messages between clients and servers located on different IP networks.

6. What Is a DHCP Lease?

A DHCP lease is the period for which a DHCP client is permitted to use an assigned IP address under the server's configuration.

A lease is not necessarily permanent. The client and server follow a renewal process to maintain the address assignment.

Lease renewal

In the standard DHCPv4 process, the client normally attempts renewal at the T1 time, which defaults to 50% of the lease duration if not otherwise specified.

If renewal with the original server is unsuccessful, the client normally enters the rebinding phase at T2, which defaults to 87.5% of the lease duration.

0% Lease begins
50% T1 renewal attempt
87.5% T2 rebinding attempt
100% Lease expires

These percentages are the standard default values. DHCP servers can provide different renewal and rebinding times.

8. DHCP Port Numbers

DHCP for IPv4 uses UDP as its transport protocol.

UDP 67

Server Port

Used by DHCP servers to receive client messages.

UDP 68

Client Port

Used by DHCP clients to receive server messages.

Remember: DHCPv4 uses UDP port 67 for the server and UDP port 68 for the client.

9. What Is a DHCP Relay Agent?

DHCP Discover messages are normally broadcast within the client's local Layer 2 broadcast domain. Routers do not ordinarily forward these broadcasts between IP networks.

What happens when the DHCP server is located on a different network?

This is where a DHCP relay agent becomes useful. A router or Layer 3 switch can receive client DHCP broadcasts and forward the requests to a remote DHCP server.

Example network

Client Network 192.168.10.0/24 DHCP Client
DHCP Broadcast →
Router DHCP Relay ip helper-address
Forwarded Request →
DHCP Server 192.168.100.10 Address Pool

Cisco DHCP relay configuration

Router(config)# interface gigabitEthernet 0/0
Router(config-if)# ip helper-address 192.168.100.10

The ip helper-address command configures the interface to relay supported UDP broadcasts, including DHCP requests, to the specified destination.

It is configured on the interface that receives the client broadcasts, pointing to the remote DHCP server.

10. Practical Lab: Configure a Cisco DHCP Server

Let's configure a Cisco router to provide IP addresses automatically to computers connected to a switch.

Lab objective

  • Build a simple LAN in Packet Tracer.
  • Configure the router's LAN interface.
  • Create a DHCP address pool.
  • Exclude selected IP addresses.
  • Configure PCs as DHCP clients.
  • Verify the assigned network settings.

Required devices

  • 1 Cisco router supporting DHCP server functionality.
  • 1 Cisco 2960 switch.
  • 2 PCs.
  • Ethernet cables.

Network topology

PC1 DHCP Client
PC2 DHCP Client
Switch Layer 2
Router DHCP Server

IP addressing plan

Parameter Value
Network192.168.10.0/24
Router Gateway192.168.10.1
DHCP Pool192.168.10.100 – 192.168.10.200
Subnet Mask255.255.255.0
DNS Server8.8.8.8

Step 1: Connect the devices

Connect PC1 and PC2 to the switch. Connect the switch to the router's GigabitEthernet 0/0 interface. Use the appropriate Ethernet connections.

Step 2: Configure the router interface

enable
configure terminal

interface gigabitEthernet 0/0
ip address 192.168.10.1 255.255.255.0
no shutdown
exit

This configures the router's LAN interface and makes it the default gateway for the client network.

Step 3: Exclude reserved IP addresses

ip dhcp excluded-address 192.168.10.1 192.168.10.99

This prevents the router's DHCP service from assigning addresses from 192.168.10.1 through 192.168.10.99.

Step 4: Create the DHCP pool

ip dhcp pool OFFICE-LAN
network 192.168.10.0 255.255.255.0
default-router 192.168.10.1
dns-server 8.8.8.8
exit

The pool defines the network and provides clients with their default gateway and DNS server information.

Because addresses 192.168.10.1 through 192.168.10.99 are excluded, the remaining eligible range in this example is 192.168.10.100 through 192.168.10.254. The pool is not restricted to ending at .200 unless additional exclusions are configured.

Step 5: Configure PCs as DHCP clients

  1. Open PC1 in Packet Tracer.
  2. Select Desktop.
  3. Open IP Configuration.
  4. Select DHCP.
  5. Repeat the process for PC2.

The PCs should receive addresses from the DHCP pool, along with the subnet mask, gateway, and DNS settings.

Step 6: Verify connectivity

Open PC1's Command Prompt and run:

ipconfig
ping 192.168.10.1

The first command displays the assigned network configuration. The second tests connectivity to the default gateway.

Expected result: Both PCs should receive valid addresses from the DHCP pool and should be able to communicate with their default gateway.

11. Useful DHCP Verification Commands

show ip dhcp binding

Displays active DHCP address bindings.

show ip dhcp pool

Displays DHCP pool information and address utilization.

show ip dhcp conflict

Displays IP addresses recorded as conflicting.

show running-config

Displays the router configuration, including DHCP settings.

ipconfig /all

Displays detailed network configuration on a Windows client.

ipconfig /release

Releases the current DHCP IPv4 configuration on Windows.

ipconfig /renew

Requests DHCP configuration again on Windows.

12. Common DHCP Problems and Troubleshooting

Client does not receive an IP address

Check physical connectivity, switch port status, VLAN assignment, DHCP pool configuration, and whether the DHCP server is reachable.

Incorrect subnet mask or gateway

Check the subnet and default-router settings in the DHCP pool. Confirm that the configuration matches the intended client network.

DHCP address pool exhausted

If all available addresses are allocated, new clients may not receive an address. Review pool utilization and lease information.

DHCP server on another subnet

Configure a DHCP relay agent on the Layer 3 interface receiving client broadcasts. Verify routing between the relay and the DHCP server.

Duplicate IP address

Review static addressing, DHCP reservations, address exclusions, and DHCP conflict records. Ensure manually assigned addresses do not overlap with dynamically allocated addresses.

Incorrect VLAN configuration

Check that the client is connected to the intended VLAN and that the corresponding DHCP scope or relay configuration is available.

13. DHCP Security Considerations

DHCP is convenient, but administrators should protect DHCP infrastructure from unauthorized configuration and malicious activity.

Rogue DHCP servers

A rogue DHCP server can provide clients with incorrect gateways, DNS servers, or IP addresses. This can disrupt connectivity or redirect network traffic.

DHCP snooping

DHCP snooping is a Layer 2 security feature supported by many managed switches. It can distinguish trusted and untrusted switch interfaces and restrict DHCP server messages arriving on untrusted ports.

Address management

Use appropriate address exclusions and reservations, monitor DHCP leases, and maintain accurate documentation.

Infrastructure protection

Restrict administrative access to DHCP servers and network devices. Keep configurations backed up and apply security updates.

14. Frequently Asked Questions

What does DHCP stand for?

DHCP stands for Dynamic Host Configuration Protocol.

What are the four steps of DHCP?

The common initial IPv4 address allocation sequence is Discover, Offer, Request, and Acknowledgment. This is known as DORA.

Which ports does DHCP use?

DHCPv4 uses UDP port 67 on the server side and UDP port 68 on the client side.

Can a router act as a DHCP server?

Yes. Many Cisco routers support DHCP server functionality and can allocate IP addresses to connected clients.

What is the difference between DHCP and DNS?

DHCP provides network configuration information to devices. DNS translates domain names into corresponding resource records, commonly including IP addresses.

What happens when DHCP is unavailable?

A device may retain a valid existing lease until it expires. A device that cannot obtain configuration may use a manually configured address or, in some environments, an automatic private IPv4 address.

Conclusion

DHCP is an essential networking protocol that automates IP address allocation and network configuration. Understanding DORA, leases, DHCP options, relay agents, and troubleshooting helps network administrators manage both small and enterprise networks.

To strengthen your understanding, configure a DHCP server in Packet Tracer, inspect the assigned leases, and experiment with different address pools and network configurations.
