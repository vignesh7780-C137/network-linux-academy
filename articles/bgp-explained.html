BGP Explained: Border Gateway Protocol

Border Gateway Protocol (BGP) is the routing protocol used to exchange routing information between autonomous systems (ASes). It plays a fundamental role in connecting networks across the Internet.

Unlike OSPF and EIGRP, which are primarily used to route traffic within an autonomous system, BGP is designed to exchange routing information between independently administered networks.

1. What Is BGP?

BGP is a path-vector exterior gateway routing protocol. It uses routing policies and path attributes to select routes between autonomous systems.

Important characteristics include:

  • Path-vector routing protocol.
  • Used for inter-domain routing.
  • Runs over TCP port 179.
  • Supports policy-based routing decisions.
  • Supports CIDR and route aggregation.
  • Uses AS_PATH to help prevent routing loops.
  • Supports eBGP and iBGP peering.

2. Understanding Autonomous Systems

An Autonomous System (AS) is a group of IP networks operated under a common routing policy and identified by an Autonomous System Number (ASN).

Organizations, Internet Service Providers and large network operators can have their own AS numbers.

Example:


AS 65001          AS 65002          AS 65003

  Router A -------- Router B -------- Router C

       eBGP              eBGP

Each autonomous system advertises reachable prefixes to its BGP neighbors according to its routing policies.

3. Public and Private AS Numbers

AS numbers are assigned by regional Internet registries and coordinated globally.

Private AS number ranges are also available for use in private routing environments.

Type 16-bit range 32-bit range
Public 1–64495 131072–4199999999
Private 64512–65534 4200000000–4294967294

AS 0 and AS 65535 are reserved in the 16-bit range. The private ranges shown are not globally unique public ASNs.

4. eBGP vs iBGP

BGP has two major peering types: External BGP (eBGP) and Internal BGP (iBGP).

External BGP (eBGP)

eBGP is used to exchange routing information between routers belonging to different autonomous systems.

Internal BGP (iBGP)

iBGP exchanges BGP routing information between routers belonging to the same autonomous system.

Feature eBGP iBGP
AS relationship Different ASes Same AS
Purpose Inter-domain routing Internal distribution of BGP routes
Typical use ISP-to-ISP peering Between routers in one organization
AS_PATH Normally prepends the advertising AS Normally does not prepend the local AS

5. BGP Neighbor Relationships

BGP routers establish neighbor relationships, also called BGP sessions or peerings, to exchange routing information.

Unlike many interior routing protocols, BGP uses TCP port 179 for reliable communication.

Important requirements include:

  • IP reachability between the peers.
  • Correct local and remote AS configuration.
  • Compatible authentication settings, if configured.
  • TCP port 179 connectivity.
  • Correct source-interface and multihop settings when required.

BGP Neighbor States

State Meaning
Idle BGP is waiting to start or restart the connection process.
Connect BGP is attempting to establish a TCP connection.
Active BGP is trying to establish the TCP connection again.
OpenSent An OPEN message has been sent.
OpenConfirm An OPEN message has been received and BGP is waiting for a KEEPALIVE.
Established The BGP session is established and can exchange routes.

6. BGP Message Types

Message Purpose
OPEN Establishes a BGP session and exchanges session parameters.
UPDATE Advertises or withdraws routing information.
KEEPALIVE Maintains the BGP session.
NOTIFICATION Reports an error and usually closes the session.
ROUTE-REFRESH Requests route re-advertisement without resetting the session, when supported.

7. Important BGP Path Attributes

BGP uses path attributes to describe routes and make routing decisions.

Attribute Purpose
AS_PATH Lists AS numbers traversed by a route.
NEXT_HOP Identifies the next-hop IP address for a route.
LOCAL_PREF Expresses preference for routes within an AS; higher is preferred.
MED Suggests a preferred entry point into an AS; lower is generally preferred when compared.
ORIGIN Indicates how a route originated.
COMMUNITY Tags routes for routing-policy decisions.
WEIGHT Cisco-specific attribute used locally on a router.

8. BGP Best-Path Selection

A BGP router may learn multiple routes to the same destination. It evaluates path attributes and routing rules to select a preferred path.

The exact decision process depends on the vendor and configuration. Common Cisco IOS decision criteria include:

  1. Highest Weight.
  2. Highest Local Preference.
  3. Locally originated routes are preferred.
  4. Shortest AS_PATH.
  5. Lowest ORIGIN type value: IGP, EGP, then Incomplete.
  6. Lowest MED, when the comparison rules permit.
  7. Prefer eBGP over iBGP.
  8. Lowest IGP metric to the BGP next hop.

Additional tie-breakers can apply. This is a simplified introduction rather than the complete vendor-specific algorithm.

9. Configuring eBGP on Cisco Routers

Consider two routers belonging to different autonomous systems. 


R1                         R2

AS 65001                  AS 65002

192.168.12.1 ----------- 192.168.12.2

R1 LAN: 192.168.1.0/24
R2 LAN: 192.168.2.0/24

R1 Configuration

enable
configure terminal

router bgp 65001
 neighbor 192.168.12.2 remote-as 65002
 network 192.168.1.0 mask 255.255.255.0

end
write memory

R2 Configuration

enable
configure terminal

router bgp 65002
 neighbor 192.168.12.1 remote-as 65001
 network 192.168.2.0 mask 255.255.255.0

end
write memory

The network command advertises a prefix only when an exact matching route exists in the routing table.

These examples assume that interface IP addressing and connected LAN networks have already been configured.

10. BGP Verification Commands

show ip bgp summary
show ip bgp
show ip bgp neighbors
show ip route bgp
show running-config

These commands help verify BGP sessions, received routes, advertised routes and routing configuration.

11. BGP Troubleshooting

Problem Possible Cause
Neighbor stuck in Active TCP connectivity failure, incorrect neighbor address or filtering.
Neighbor stuck in Idle Configuration issue or BGP process not progressing.
Routes not advertised Missing exact route in the routing table or incorrect network statement.
Routes not installed Unreachable next hop or another route-selection issue.
Session rejected Remote AS mismatch or incompatible session parameters.

12. Practical Packet Tracer Lab

Build a two-AS BGP network using two Cisco routers.

  1. Connect R1 and R2 through an Ethernet link.
  2. Configure the link IP addresses.
  3. Configure one LAN behind each router.
  4. Assign AS 65001 to R1 and AS 65002 to R2.
  5. Configure eBGP neighbors.
  6. Advertise the LAN prefixes using network statements.
  7. Verify that the BGP neighbor state becomes Established.
  8. Inspect the BGP table.
  9. Test communication between end devices.

Packet Tracer support for BGP depends on the router model and simulated IOS version. Verify that your selected devices support the required commands.

13. Key Takeaways

  • BGP is a path-vector routing protocol.
  • BGP is used for routing between autonomous systems.
  • It uses TCP port 179.
  • eBGP connects different ASes.
  • iBGP distributes BGP routes within the same AS.
  • AS_PATH helps prevent routing loops.
  • Path attributes influence BGP route selection.
  • The Established state indicates a working BGP session.

Conclusion

BGP is one of the most important routing protocols in modern networking. Understanding autonomous systems, peer relationships, path attributes and route selection provides a foundation for studying Internet routing and enterprise network design.
