Inter-VLAN Routing Explained

VLANs divide a switched network into separate logical broadcast domains. However, devices belonging to different VLANs cannot communicate directly through Layer 2 switching alone.

Inter-VLAN routing allows devices in different VLANs to communicate through a Layer 3 device, such as a router or Layer 3 switch.

1. Why Do We Need Inter-VLAN Routing?

Imagine an organization with three departments:

  • VLAN 10 – Administration
  • VLAN 20 – Engineering
  • VLAN 30 – Finance

Each VLAN represents a separate broadcast domain. A computer in VLAN 10 cannot directly communicate with a computer in VLAN 20 without a Layer 3 routing function.

2. Methods of Inter-VLAN Routing

There are two commonly used approaches:

Method 1: Router-on-a-Stick

Router-on-a-Stick uses one physical router interface connected to a switch trunk port. The router interface is divided into multiple logical subinterfaces, with each subinterface handling a particular VLAN.

How It Works

  1. A switch receives traffic from a device in a VLAN.
  2. The switch forwards the traffic through a trunk link.
  3. The 802.1Q VLAN tag identifies the originating VLAN.
  4. The router's corresponding subinterface processes the packet.
  5. The router routes the packet toward the destination VLAN.
  6. The packet returns through the trunk with the appropriate VLAN tag.

Router-on-a-Stick Configuration

Example topology:

PC1 --- VLAN 10
          |
       SWITCH
          |
       TRUNK
          |
       ROUTER

Example addressing:

VLAN 10: 192.168.10.0/24
Gateway: 192.168.10.1

VLAN 20: 192.168.20.0/24
Gateway: 192.168.20.1

Configure the switch:

enable
configure terminal

vlan 10
name ADMIN
exit

vlan 20
name ENGINEERING
exit

interface gigabitEthernet 0/1
switchport mode trunk
no shutdown
exit

Configure the router:

enable
configure terminal

interface gigabitEthernet 0/0
no shutdown
exit

interface gigabitEthernet 0/0.10
encapsulation dot1Q 10
ip address 192.168.10.1 255.255.255.0
exit

interface gigabitEthernet 0/0.20
encapsulation dot1Q 20
ip address 192.168.20.1 255.255.255.0
exit

The subinterfaces act as the default gateways for their respective VLANs.

3. Method 2: Layer 3 Switch Using SVIs

A Layer 3 switch can perform routing internally without requiring a separate external router for every VLAN.

It uses Switched Virtual Interfaces (SVIs), which are logical Layer 3 interfaces associated with VLANs.

Layer 3 Switch Configuration

enable
configure terminal

ip routing

vlan 10
name ADMIN
exit

vlan 20
name ENGINEERING
exit

interface vlan 10
ip address 192.168.10.1 255.255.255.0
no shutdown
exit

interface vlan 20
ip address 192.168.20.1 255.255.255.0
no shutdown
exit

The ip routing command enables Layer 3 routing on supported Cisco switches.

4. Router-on-a-Stick vs Layer 3 Switching

Feature Router-on-a-Stick Layer 3 Switch
Routing device Router Layer 3 switch
Logical interfaces Subinterfaces SVIs
Inter-VLAN connection Trunk link to router Internal Layer 3 routing
Typical use Small networks and labs Enterprise networks

5. Verification Commands

Useful Cisco IOS commands include:

show vlan brief

show interfaces trunk

show ip interface brief

show ip route

show running-config

show interfaces switchport

6. Common Troubleshooting Problems

  • Incorrect VLAN assignment on access ports.
  • Trunk link not configured correctly.
  • Incorrect 802.1Q VLAN ID.
  • Incorrect default gateway on end devices.
  • SVI interface not operational.
  • IP routing not enabled on the Layer 3 switch.
  • Incorrect IP address or subnet mask.

7. Practical Lab Challenge

Build a network with two VLANs and two computers in each VLAN. Configure inter-VLAN routing and verify communication between all four computers.

Test connectivity using the ping command. Then deliberately introduce a configuration error and troubleshoot it.

Conclusion

Inter-VLAN routing enables communication between logically separated networks. Router-on-a-Stick uses router subinterfaces, while Layer 3 switches use SVIs to perform routing.

Understanding both methods is important for configuring, maintaining and troubleshooting enterprise networks.
