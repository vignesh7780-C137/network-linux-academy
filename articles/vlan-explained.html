1. What Is a VLAN?

VLAN stands for Virtual Local Area Network. It is a logical method of dividing a physical switched network into separate Layer 2 networks.

Without VLANs, devices connected to the same Layer 2 broadcast domain generally belong to one logical network. VLANs allow administrators to create separate broadcast domains using the same physical switching infrastructure.

Simple definition: A VLAN allows a network administrator to logically separate devices into different Layer 2 networks, even when those devices connect to the same physical switch.

Real-world example

Imagine an organization with three departments:

VLAN 10

Administration

192.168.10.0/24

VLAN 20

Engineering

192.168.20.0/24

VLAN 30

Guest Network

192.168.30.0/24

All three departments may use the same physical switches, but their Layer 2 traffic is logically separated.

2. Why Do We Use VLANs?

Network segmentation

VLANs allow administrators to separate departments, devices, and services without requiring a completely separate physical switching network for every group.

Smaller broadcast domains

Broadcast traffic within one VLAN is not normally forwarded into another VLAN by a Layer 2 switch. This limits the scope of broadcast traffic.

Improved administration

Devices can be grouped according to their purpose rather than their physical location.

Security policy separation

VLANs create logical separation. Administrators can then use Layer 3 access-control policies and firewalls to control communication between VLANs.

VLANs provide segmentation, but they are not a complete security solution. Traffic between VLANs must be controlled using appropriate Layer 3 policies and security controls.

3. Understanding Broadcast Domains

A broadcast is a frame sent to all devices within the relevant Layer 2 broadcast domain.

For example, when a device sends an Ethernet broadcast, a switch forwards it through eligible ports belonging to the same VLAN, except the port on which it arrived.

One broadcast domain without VLAN separation

Layer 2 Switch
PC 1
PC 2
PC 3

All three devices belong to the same broadcast domain in this simplified example.

Separate broadcast domains using VLANs

Layer 2 Switch
VLAN 10 PC 1
VLAN 20 PC 2
VLAN 30 PC 3

Each VLAN represents a separate Layer 2 broadcast domain.

4. How Do VLANs Work?

A managed Ethernet switch maintains VLAN membership information. When an administrator assigns a switch interface to a VLAN, the switch handles frames according to that interface's VLAN membership and switching rules.

  1. An administrator creates VLANs on the switch.
  2. Switch ports are assigned to the appropriate VLANs.
  3. Devices connect to those ports.
  4. The switch forwards frames within the appropriate VLAN.
  5. Communication between different VLANs requires Layer 3 routing.

Example IP addressing plan

10Administration192.168.10.0/24192.168.10.1

These IP networks are an example addressing plan. VLAN IDs and IP subnets are different concepts, although network administrators commonly associate one IP subnet with each VLAN.

5. Common Types of VLANs

Data VLAN

Carries ordinary user traffic such as web browsing, file transfers, and application communication.

Voice VLAN

Used for IP phone traffic. Voice VLANs can be combined with Quality of Service policies to help prioritize voice traffic.

Management VLAN

Used to access and manage network devices through protocols such as SSH, SNMP, or a management interface.

Native VLAN

On an IEEE 802.1Q trunk, the native VLAN identifies traffic that is sent untagged by default. Both ends of a trunk should have matching native VLAN settings.

6. Access Ports vs Trunk Ports

Access port

An access port normally belongs to one data VLAN and is commonly used to connect end devices such as computers and printers. 

Switch(config)# interface fastEthernet 0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 10

Trunk port

A trunk port carries traffic for multiple VLANs over a single physical connection. It is commonly used between switches or between a switch and a router or Layer 3 device. 

Switch(config)# interface gigabitEthernet 0/1
Switch(config-if)# switchport mode trunk
Feature Access Port Trunk Port
Typical purposeEnd-device connectionNetwork-device connection
VLAN membershipOne data VLANMultiple VLANs
802.1Q taggingUsually untagged at the endpointTags VLAN traffic, except native VLAN traffic by default
Common examplePC to switchSwitch to switch

7. What Is IEEE 802.1Q Tagging?

IEEE 802.1Q is the standard used to identify VLAN membership in Ethernet frames carried over VLAN-aware bridged networks.

When a frame is carried across a trunk, an 802.1Q tag identifies the VLAN associated with that frame. The tag includes a VLAN Identifier (VID).

Simplified tagged Ethernet frame

Destination MAC Source MAC 802.1Q Tag EtherType / Length Payload FCS

The VLAN tag contains information used to identify the frame's VLAN.

The VLAN Identifier field is 12 bits long. Values 1 through 4094 are available for ordinary VLAN identification; VLAN ID 0 and 4095 have special meanings.

The native VLAN on a typical Cisco 802.1Q trunk carries untagged traffic by default. Other VLAN traffic is normally tagged.

8. How Do Different VLANs Communicate?

Devices in different VLANs belong to different Layer 2 broadcast domains. A Layer 2 switch does not route frames directly between those VLANs.

To communicate, traffic must pass through a Layer 3 routing device. This process is called inter-VLAN routing.

Common inter-VLAN routing methods

Router-on-a-stick

A router uses one physical Ethernet interface with multiple logical subinterfaces. Each subinterface is associated with a VLAN using 802.1Q encapsulation.

Layer 3 switch

A multilayer switch uses switched virtual interfaces (SVIs) to provide gateways and route traffic between VLANs.

A VLAN creates Layer 2 separation. A router or Layer 3 switch provides the routing required for communication between different VLANs.

9. Practical Lab: Configure VLANs in Cisco Packet Tracer

Now let's create a small network and configure VLANs ourselves.

Lab objective

Create two VLANs, assign computers to them, configure a trunk between two switches, and verify connectivity.

Required devices

  • 2 Cisco 2960 switches
  • 4 PCs
  • Ethernet connections
  • Cisco Packet Tracer

Topology and connections

Switch 1 Fa0/24 — Trunk
Trunk link Fa0/24 ↔ Fa0/24
Switch 2 Fa0/24 — Trunk
Switch 1 Fa0/1 — PC1 — VLAN 10 Fa0/2 — PC2 — VLAN 20
Switch 2 Fa0/1 — PC3 — VLAN 10 Fa0/2 — PC4 — VLAN 20

IP addressing

PC VLAN IP Address Subnet Mask
PC110192.168.10.11255.255.255.0
PC310192.168.10.13255.255.255.0
PC220192.168.20.12255.255.255.0
PC420192.168.20.14255.255.255.0

No default gateway is required for this particular same-VLAN connectivity test because we are not routing between different IP networks.

Step 4: Create the same VLANs on Switch 2

exit

exit

Step 5: Assign access ports on Switch 2

switchport mode access
switchport access vlan 10
exit

interface fastEthernet 0/2
switchport mode access
switchport access vlan 20
exit

Step 6: Configure the trunk on Switch 2

switchport mode trunk
exit

Step 7: Configure PC IP addresses

Open each PC in Packet Tracer, select Desktop, then IP Configuration. Enter the IP address and subnet mask from the addressing table.

Step 8: Test connectivity

From PC1, open Command Prompt and test: 

ping 192.168.10.13

PC1 and PC3 are in VLAN 10. The ping should succeed after the network has converged and the links are operational.

Now try: 

ping 192.168.20.12

This ping should fail because PC1 and PC2 are in different VLANs and no inter-VLAN routing has been configured.

Lab result: PCs in the same VLAN can communicate across the trunk. PCs in different VLANs cannot communicate until a Layer 3 routing solution is configured.

10. Useful VLAN Verification Commands

Use these commands on Cisco switches to inspect VLANs and trunks.

show vlan brief

Displays VLAN IDs, names, status, and access-port membership.

show interfaces trunk

Displays operational trunk ports and VLAN information.

show interfaces fa0/24 switchport

Displays the switchport mode and VLAN-related configuration of an interface.

show running-config

Displays the active configuration, including VLAN and interface settings.

11. Common VLAN Problems and Troubleshooting

Incorrect VLAN assignment

A PC may be connected to a switch port assigned to the wrong VLAN. Check the port membership with show vlan brief.

Trunk not configured

If VLAN traffic needs to travel between switches, verify that the connecting interfaces are operational trunks.

VLAN missing on the other switch

Ensure that the required VLAN exists and is active on the relevant switches.

VLAN not allowed on trunk

Check the trunk's allowed VLAN list. A VLAN excluded from that list cannot use that trunk.

Native VLAN mismatch

Ensure both ends of an 802.1Q trunk use the intended matching native VLAN.

Incorrect IP addressing

Devices in the same VLAN should have compatible IP addressing for their intended subnet. Check their addresses and subnet masks.

12. VLAN Security Best Practices

  • Do not treat VLAN separation as a replacement for firewall rules or access-control policies.
  • Disable unused switch ports or place them in an appropriately isolated unused VLAN.
  • Use dedicated management access and restrict who can reach network-device management interfaces.
  • Restrict trunk links to the VLANs that actually need to cross them.
  • Configure trunking explicitly where appropriate and disable unnecessary negotiation.
  • Use consistent native VLAN settings on both ends of trunk links.
  • Monitor VLAN and switch configuration changes.

VLAN hopping and trunk misconfiguration are examples of risks that network administrators should understand when designing switched networks.

13. Frequently Asked Questions

Can multiple VLANs exist on one physical switch?

Yes. A managed switch can support multiple VLANs, subject to its hardware and software capabilities.

Can two devices in different VLANs communicate?

Yes, but communication requires routing through a Layer 3 device, subject to the applicable routing and security policies.

What is the difference between a VLAN and a subnet?

A VLAN is a Layer 2 logical broadcast domain. An IP subnet is a Layer 3 addressing concept. Networks commonly map one IP subnet to one VLAN, but they are not the same thing.

What is VLAN 1?

VLAN 1 is the default VLAN on many Cisco switches. Administrators should plan VLAN usage carefully rather than automatically using the default VLAN for ordinary user and management traffic.

What is the difference between an access port and a trunk port?

An access port normally carries one data VLAN, while a trunk port carries traffic for multiple VLANs across a shared link.

Conclusion

VLANs are an essential part of modern switched networks. They allow network administrators to logically segment devices, manage broadcast domains, and organize network infrastructure.

Understanding access ports, trunk ports, 802.1Q tagging, and inter-VLAN routing provides a strong foundation for more advanced switching and enterprise networking.

The best way to master VLANs is to configure them, test connectivity, and troubleshoot mistakes in a network simulator.
