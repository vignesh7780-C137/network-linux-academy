VLAN Trunking Explained: Understanding IEEE 802.1Q

VLANs divide a physical switch network into separate logical broadcast domains. But what happens when multiple VLANs need to communicate across different switches? This is where VLAN trunking becomes important.

1. What Is VLAN Trunking?

VLAN trunking is a method of carrying traffic from multiple VLANs over a single network link between networking devices.

Instead of using a separate physical connection for every VLAN, a trunk link can carry traffic belonging to several VLANs.

2. Access Port vs Trunk Port

Access Port

An access port normally belongs to one VLAN. It is commonly used to connect end devices such as computers, printers and ordinary servers.

Trunk Port

A trunk port carries traffic for multiple VLANs. It is commonly used between switches and between switches and other VLAN-aware devices.

Feature Access Port Trunk Port
VLANs carried Normally one data VLAN Multiple VLANs
Common connection End devices Switch-to-switch links
802.1Q tagging Usually untagged on the access link Tags identify VLANs on the trunk, except native VLAN traffic in traditional Cisco configurations

3. What Is IEEE 802.1Q?

IEEE 802.1Q is the standard used to identify VLAN membership in Ethernet frames when they travel across a VLAN-aware network.

It inserts a four-byte VLAN tag into the Ethernet frame. This tag contains information used by network devices to identify the VLAN.

The 802.1Q Tag Contains

  • TPID: Tag Protocol Identifier, commonly 0x8100.
  • PCP: Priority Code Point, used for traffic priority.
  • DEI: Drop Eligible Indicator.
  • VID: VLAN Identifier, identifying the VLAN.

4. Understanding the Native VLAN

In traditional Cisco 802.1Q trunk configurations, the native VLAN carries untagged frames over the trunk link.

By default, many Cisco switch configurations use VLAN 1 as the native VLAN, but administrators can configure a different VLAN.

For security and consistency, both ends of a trunk should use the same native VLAN.

5. Allowed VLANs

A trunk does not have to carry every VLAN in the network. Administrators can restrict which VLANs are permitted across a trunk.

This reduces unnecessary traffic and helps control which VLANs can cross a particular link.

6. Cisco Switch Configuration

Consider two switches connected through GigabitEthernet 0/1. We want VLANs 10, 20 and 30 to travel across the connection.

Configure Switch 1

enable
configure terminal

vlan 10
 name SALES

vlan 20
 name HR

vlan 30
 name IT

interface gigabitEthernet 0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30

end
write memory

Configure Switch 2

enable
configure terminal

vlan 10
 name SALES

vlan 20
 name HR

vlan 30
 name IT

interface gigabitEthernet 0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30

end
write memory

The VLANs must exist on the switches where they are needed. The physical interfaces must also be connected and configured compatibly.

7. Changing the Native VLAN

Example: change the native VLAN to VLAN 99 on both ends of the trunk. 

configure terminal

vlan 99
 name NATIVE

interface gigabitEthernet 0/1
 switchport trunk native vlan 99

end

Configure the same native VLAN on the connected switch port to avoid a native VLAN mismatch.

8. Verification Commands

show vlan brief

show interfaces trunk

show interfaces gigabitEthernet 0/1 switchport

show running-config interface gigabitEthernet 0/1

9. Common Trunking Problems

  • One switch port is configured as access while the other is expected to trunk.
  • VLANs are missing from one of the switches.
  • The required VLAN is not included in the allowed VLAN list.
  • Native VLAN mismatch between trunk endpoints.
  • Physical cable or interface problems.
  • Platform-specific trunk encapsulation or configuration differences.

10. Practical Packet Tracer Lab

Build a small network using two Cisco switches and four PCs.

  1. Create VLAN 10 and VLAN 20 on both switches.
  2. Connect two PCs to each switch.
  3. Assign the PCs to the appropriate VLANs.
  4. Connect the two switches using a trunk link.
  5. Allow VLANs 10 and 20 on the trunk.
  6. Test connectivity between PCs in the same VLAN.
  7. Test connectivity between different VLANs.

Expected result: PCs in the same VLAN can communicate across the trunk when their IP configuration is correct. Different VLANs need a Layer 3 routing function to communicate with one another.

11. Frequently Asked Questions

Can a trunk carry multiple VLANs?

Yes. That is the primary purpose of VLAN trunking.

Does a trunk port have an IP address?

A normal Layer 2 switch trunk port does not require an IP address. Layer 3 interfaces are used for routing.

What happens if the native VLANs do not match?

Untagged traffic may be assigned to different VLANs at opposite ends, potentially causing connectivity and security problems.

Conclusion

VLAN trunking allows multiple VLANs to share a physical connection. Understanding access ports, trunk ports, 802.1Q tags, native VLANs and allowed VLANs is essential for configuring switched networks.
