Linux Command Line Basics: A Practical Beginner's Guide

Learn how to work confidently in a Linux terminal: move around the filesystem, manage files, inspect your system, and understand basic permissions.

Beginner Level Linux Administration 12–15 min read

1. Introduction to the Linux Command Line

Linux is widely used on servers, network appliances, cloud platforms, and development systems. Administrators often manage these systems through a command-line interface (CLI), where they enter commands to inspect and control the operating system.

The command line may look unfamiliar at first, but most daily tasks use a relatively small set of commands. The goal of this guide is to help you understand what those commands do, not simply memorize them.

Where to practise: Use a Linux virtual machine or a Linux environment you control. The examples below are intended for a personal learning system, not an unfamiliar production server.

2. The Terminal and the Shell

A terminal is the interface where you type and view text. A shell is the program that interprets the commands you enter. Bash is a common shell on Linux systems, although other shells are available.

When you open a terminal, you may see a prompt similar to this:

learner@linux-lab:~$
The prompt commonly shows the username, computer name, current directory, and a symbol indicating whether the shell is running with ordinary-user or elevated privileges.

Enter a command and press Enter. The shell interprets it and displays output or an error message. Linux commands are generally case-sensitive: Documents and documents can be different names.

Get help

  • man ls — open the manual page for ls.
  • ls --help — display a short help summary where supported.
  • history — display commands entered earlier in the current shell history.
  • clear — clear the visible terminal screen.

3. Understanding the Linux Filesystem

Linux organizes files and directories in a single directory tree. The top of this tree is the root directory, written as /. This is different from the administrator account named root.

DirectoryTypical purpose
/Top of the filesystem hierarchy
/homePersonal directories for ordinary users
/etcSystem-wide configuration files
/varVariable data such as logs and caches
/tmpTemporary files
/usrMany user-space programs and shared resources
/bin and /sbinEssential command locations; on many modern distributions these may link into /usr
/devDevice files exposed to the system
/bootFiles needed to start the system

Two path styles are important:

  • Absolute path: starts at /, such as /home/learner/Documents.
  • Relative path: starts from your current directory, such as Documents/notes.txt.
Special path symbols: . means the current directory, .. means the parent directory, and ~ usually represents your home directory.

4. Navigate Directories

Start with three commands used constantly by Linux administrators:

  • pwd — print the current working directory.
  • ls — list files and directories.
  • cd — change the current directory.

Useful examples

pwd — show where you are.

ls -l — show a detailed listing.

ls -la — include hidden entries.

cd /etc — move to the system configuration directory.

cd .. — move one directory up.

cd ~ — return to your home directory.

cd - — return to the previous working directory.

In Linux, names beginning with a dot, such as .bashrc, are hidden from a normal ls listing. Use ls -a to display them.

5. Create, Copy, Move, and Remove Files

These commands help you organize your work and manage files from the terminal.

Build a safe practice folder

Run these commands from your home directory to create a small workspace:

mkdir -p ~/linux-practice/notes

cd ~/linux-practice

touch notes/first-session.txt

cp notes/first-session.txt notes/first-session-copy.txt

mv notes/first-session-copy.txt notes/backup.txt

ls -l notes

Be careful with deletion: rm normally removes files without sending them to a graphical recycle bin. Check the path before pressing Enter. Avoid experimenting with recursive or forced deletion options, especially with elevated privileges.

6. Read and Search Text Files

Linux administrators frequently inspect configuration files and logs. These commands help you read text without needing a graphical editor.

  • cat file.txt — print the file contents.
  • less file.txt — read a long file page by page; press q to quit.
  • head file.txt — display the first lines.
  • tail file.txt — display the last lines.
  • tail -f app.log — follow new lines added to a log file; press Ctrl+C to stop.
  • grep "error" app.log — search for matching text.
  • find ~/linux-practice -name "*.txt" — find text files beneath the practice directory.

For example, grep -i "failed" auth.log searches for the word regardless of letter case. You need appropriate read permission to inspect a file.

8. Understand Linux File Permissions

Linux permissions control who can read, modify, or execute a file. A detailed listing such as ls -l may show a permission string like this:

-rwxr-xr--
The first character indicates the file type. The remaining nine characters are grouped into permissions for the owner, group, and others.
SymbolMeaning for a regular fileNumeric value
rRead the file4
wModify the file2
xExecute the file1
-Permission not granted0

The chmod command changes permissions. For example, chmod 640 notes.txt gives the owner read/write permission, the group read permission, and others no permission. The three digits correspond to owner, group, and others.

You can also use symbolic permissions: chmod u+x script.sh adds execute permission for the file owner.

Ownership is managed with chown, which normally requires administrator privileges. Do not change ownership or permissions on system files unless you understand why it is necessary.

Directory permissions differ: read allows listing names, write allows creating or removing entries (subject to other controls), and execute allows traversing/searching the directory.

9. Useful Linux Network Commands

Linux is common in network administration, so it is useful to know a few commands for inspecting network configuration and connectivity.

  • ip addr — display network interfaces and IP addresses.
  • ip route — display the routing table.
  • ping -c 4 1.1.1.1 — send four ICMP echo requests to test reachability.
  • ss -tuln — display listening TCP and UDP sockets.
  • hostname -I — display assigned IP addresses on many Linux distributions.

A successful ping does not prove that every application service is working, and a failed ping does not always mean the destination is offline. Firewalls and network policies may block ICMP.

10. Hands-on Practice: Your First Linux Workspace

Use your own Linux virtual machine and complete these tasks. Try each one before looking at the suggested command.

  1. Display your current directory. Hint: use pwd.
  2. Go to your home directory and create a folder named network-lab. Hint: use cd and mkdir.
  3. Inside it, create a file named lab-notes.txt. Hint: use touch.
  4. Copy the file to lab-notes-backup.txt. Hint: use cp.
  5. Display both files in a detailed listing. Hint: use ls -l.
  6. Check your Linux distribution and IP configuration. Hint: inspect /etc/os-release and use ip addr.
  7. Set the original file's permissions to owner read/write and group read. Hint: use chmod 640 lab-notes.txt.
Practice objective: You should be able to explain what each command changes, identify your current directory, and recognize basic file permissions. Repeat the exercise until you can complete it without copying the examples.

Frequently Asked Questions

Do I need to memorize every Linux command?

No. Learn the commands you use often and become comfortable reading manual pages and help output. Knowing how to find reliable help is an important administration skill.

Is the terminal the same as the shell?

No. The terminal provides the text interface; the shell interprets commands entered through it.

Should I use sudo for every command?

No. Use ordinary user privileges for routine work. Use sudo only when a task genuinely requires administrator permissions and you understand the command.

Are Linux commands identical on every distribution?

Many core commands are shared, but package managers, service tools, default paths, and some options can vary between distributions.

Conclusion

The Linux command line becomes easier with regular practice. Start with navigation, file management, text inspection, system information, and permissions. These fundamentals will prepare you for later topics such as users and groups, package management, services, SSH, firewall configuration, and Linux network administration.
