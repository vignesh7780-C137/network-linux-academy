Linux Users and Groups: A Practical Administration Guide

Understand how Linux identifies users, organizes groups, controls account access, and grants administrative privileges safely.

Beginner to Intermediate Linux Administration 12–15 min read

1. Introduction to Linux User and Group Management

Linux is a multi-user operating system. Multiple people and services can use the same machine while receiving different permissions. The operating system uses user accounts and groups to decide who can access files, run programs, and perform administrative tasks.

For a system administrator, account management is a core security responsibility. Each person should use an individual account, receive only the access required for their role, and have access removed when it is no longer needed.

Lab safety: Practise these commands in a Linux virtual machine that you control. Some commands require administrator privileges and can change real account access. Do not experiment on a shared or production server.

2. Users, UIDs and GIDs

A user account represents an identity on the Linux system. Linux internally identifies each account with a numeric User ID (UID), while a Group ID (GID) identifies a group.

  • Username: a readable account name, such as alex.
  • UID: the numeric identifier assigned to the user.
  • Primary group: the main group associated with the account.
  • Supplementary groups: additional groups that provide extra access.
  • System accounts: accounts commonly used by services and operating-system components rather than interactive people.

Many Linux distributions reserve low UID ranges for system accounts and use higher values for ordinary users. Exact ranges depend on the distribution's configuration.

Important distinction: The account named root normally has UID 0 and has extensive system privileges. A username is not what makes an account powerful; its UID and granted permissions determine its effective identity and access.

3. Important Linux Account Files

Linux stores local account and group information in several files. Administrators should know what each file is for, but should use account-management commands rather than manually editing these files in ordinary situations.

FilePurpose
/etc/passwdAccount names, UIDs, GIDs, home directories and login shells.
/etc/shadowPassword hashes and password-aging information; normally restricted to privileged access.
/etc/groupLocal group names, GIDs and supplementary group membership.
/etc/gshadowProtected group administration information on systems that use it.
/etc/skelTemplate files copied into newly created home directories by common account tools.

A typical /etc/passwd entry contains seven colon-separated fields:

alex:x:1001:1001:Alex User:/home/alex:/bin/bash
  1. alex — username.
  2. x — indicates that the password information is stored separately, commonly in /etc/shadow.
  3. 1001 — UID.
  4. 1001 — primary GID.
  5. Alex User — optional descriptive field.
  6. /home/alex — home directory.
  7. /bin/bash — login shell.
Security note: Do not copy, publish, or casually modify password hashes. Protect /etc/shadow and use supported account tools for changes.

4. Inspect Existing Users and Groups

Before changing an account, inspect its current identity and group membership.

CommandPurpose
whoamiShow the effective username.
idShow your UID, primary GID and supplementary groups.
id alexInspect the identity of user alex.
getent passwdDisplay account records from configured identity sources.
getent groupDisplay group records.
groups alexShow groups associated with alex.
whoShow users currently logged in.
lastShow recorded login history when the system maintains it.

getent is useful because it queries the system's configured name-service sources. On centrally managed systems, account information may come from a directory service rather than only local files.

5. Create and Configure a User

The useradd command creates an account. On many distributions, adduser is also available as a friendlier interactive tool or wrapper. Options and defaults can vary, so consult the manual page for your distribution.

sudo useradd -m -s /bin/bash learner1

sudo passwd learner1

id learner1

In this example:

  • sudo runs the account-management command with elevated privileges.
  • useradd creates the account.
  • -m requests creation of a home directory.
  • -s /bin/bash selects Bash as the login shell.
  • passwd sets or changes the account password interactively.

Use a unique username and follow your organization's password and identity policies. Never place a real password directly into a command that may be saved in shell history.

6. Password and Account Expiry Management

The passwd command changes passwords and can lock or unlock password authentication for an account, depending on the options used. Password aging can be inspected and configured with chage.

sudo passwd learner1 — interactively change the password.

sudo passwd -l learner1 — lock the account's password authentication.

sudo passwd -u learner1 — unlock password authentication when appropriate.

sudo chage -l learner1 — inspect password aging information.

Locking a password is not always the same as fully disabling an account. Existing sessions, SSH keys, other authentication methods, and scheduled processes may remain usable. For offboarding, review all access paths rather than relying on one command.

7. Create Groups and Manage Membership

Groups make it easier to assign permissions to several users at once. For example, a team group can be granted access to a shared project directory without changing each user's individual account identity.

sudo groupadd netadmins — create a group.

sudo usermod -aG netadmins learner1 — add learner1 to the supplementary group.

groups learner1 — inspect group membership.

getent group netadmins — inspect the group record.

Why use -aG? The -a option appends the group while -G specifies supplementary groups. Omitting -a when using -G can replace the user's existing supplementary group list. Always verify membership after making a change.

A user may need to start a new login session before updated group membership is reflected in their processes.

8. Administrative Access and sudo

Linux separates ordinary user activity from privileged system administration. The sudo command allows an authorized user to run a particular command with elevated privileges, subject to the system's policy.

  • Use an ordinary account for daily work.
  • Use sudo only for tasks that require elevated privileges.
  • Review the exact command before confirming it.
  • Follow the distribution's approved method for granting administrative access.

Some distributions use a group named sudo; others commonly use wheel. Membership alone does not guarantee access unless the sudo policy is configured to grant it.

Safe configuration: Use visudo to edit sudo policy because it checks syntax before saving. Prefer a carefully scoped rule in a file under /etc/sudoers.d/ when appropriate. Never grant unrestricted administrative access without a clear need.

9. Home Directories and Login Shells

A home directory is a user's personal working area. It commonly stores documents, configuration files and application data. The login shell is the command interpreter started for an interactive login.

getent passwd learner1 — inspect the account's configured home directory and shell.

sudo usermod -d /home/learner1 -m learner1 — set a home directory and request moving existing contents.

sudo usermod -s /bin/bash learner1 — change the login shell.

Not every account should have an interactive shell. Service accounts may use a non-login shell such as /usr/sbin/nologin where supported and appropriate. Check the path available on your distribution before configuring it.

10. Disable or Remove an Account

When a user no longer needs access, administrators should follow an offboarding process. First identify ownership of files, running services, scheduled jobs, SSH keys and other credentials. Preserve data according to organizational policy.

sudo passwd -l learner1 — lock password authentication.

sudo userdel learner1 — remove the account entry without requesting home-directory removal.

sudo userdel -r learner1 — request removal of the account and its home directory and mail spool, where applicable.

Warning: Account deletion can remove data and disrupt services. Do not run userdel -r until you have confirmed backups, file ownership, service dependencies and retention requirements. On managed systems, follow the central identity provider's offboarding procedure.

11. Hands-on Lab: Create a User and Group

Perform this exercise in a disposable Linux virtual machine where you have administrator access. The commands create a test account and group.

  1. Create a group named labteam.
  2. Create a user named labuser with a home directory and Bash shell.
  3. Set a password interactively.
  4. Add the user to the labteam supplementary group.
  5. Check the user's UID, primary GID and supplementary groups.
  6. Inspect the account record using getent passwd labuser.
  7. Inspect the group record using getent group labteam.

Suggested command sequence

sudo groupadd labteam

sudo useradd -m -s /bin/bash labuser

sudo passwd labuser

sudo usermod -aG labteam labuser

id labuser

getent passwd labuser

getent group labteam

After completing the lab, explain the difference between a UID and a GID, why -aG is used, and why group membership may require a new login session to take effect.

12. Linux Account Security Checklist

  • Give each person an individual account; avoid shared human logins.
  • Grant only the groups and privileges required for the person's role.
  • Use sudo according to a reviewed policy rather than sharing the root password.
  • Protect /etc/shadow and other sensitive account data.
  • Review inactive accounts and remove access when it is no longer required.
  • Check SSH keys and other authentication methods during offboarding.
  • Keep a record of administrative changes and follow organizational policy.

Frequently Asked Questions

What is the difference between a user and a group?

A user represents an account identity. A group is a collection used to manage shared access to files and resources.

What is the difference between UID and GID?

UID identifies a user; GID identifies a group. Linux uses these numeric identifiers when checking ownership and permissions.

Does locking a password completely disable an account?

Not necessarily. Other authentication methods or existing sessions may remain active. Review all access paths when disabling an account.

Why should I use usermod -aG instead of usermod -G?

The append option preserves existing supplementary group membership while adding the new group. Without it, the supplementary group list may be replaced.

Conclusion

User and group management is central to Linux security. Understanding UIDs, GIDs, account files, group membership and sudo helps administrators control access consistently. Practise these tasks in a virtual machine before applying them to real servers.
