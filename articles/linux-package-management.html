Linux Package Management: A Practical Guide to APT, DNF and RPM

Learn how Linux installs, updates, verifies and removes software while handling dependencies and trusted repositories.

1. Introduction to Linux Package Management

Linux software is commonly distributed as packages. A package contains an application or component together with metadata such as its version, architecture, dependencies and installation instructions. A package manager helps administrators install software, keep it updated and remove it consistently.

Instead of downloading random program files and copying them into system directories, administrators normally use the package manager provided by their distribution. This makes software maintenance more predictable and helps track which files belong to which packages.

Lab safety: Practise in a Linux virtual machine that you control. Installing, removing and upgrading packages changes the operating system. Read the proposed transaction before confirming it, especially on a production server.

2. Packages, Repositories and Dependencies

What is a package?

A package is a structured software bundle. It usually includes program files, configuration defaults, metadata and sometimes scripts that run during installation or removal.

What is a repository?

A repository is a software source maintained by a distribution or another trusted provider. Package managers retrieve package indexes and software from configured repositories. Repositories may be official distribution mirrors, an organization's internal mirror or a vendor's supported repository.

What are dependencies?

An application may rely on shared libraries or other programs. These requirements are called dependencies. A package manager resolves dependencies and proposes the additional packages needed to complete an installation.

TermMeaning
PackageA managed software bundle with metadata.
RepositoryA configured source of packages and package metadata.
DependencyAnother package or component required by software.
Package index / metadataInformation used to locate package versions and dependencies.
Package managerThe tool that resolves, installs, upgrades and removes packages.

3. Common Linux Package Families

Different Linux distributions use different package formats and higher-level package managers. The two major families you will commonly encounter are Debian-based and Red Hat-based systems.

Distribution familyCommon distributionsPackage formatHigh-level manager
DebianDebian, Ubuntu, Linux Mint.debapt
Red HatRHEL, Rocky Linux, AlmaLinux, Fedora.rpmdnf (older systems may use yum)

APT and DNF are high-level tools: they work with repositories and resolve dependencies. dpkg and rpm are lower-level tools that work directly with local package files and installed package records.

Remember: APT does not install RPM packages, and DNF does not install Debian packages. First identify the distribution, then use its supported package tools.

4. APT on Debian and Ubuntu

APT (Advanced Package Tool) is commonly used on Debian-based distributions. Most administrative operations require sudo.

Refresh package information

sudo apt update

This downloads the latest package index information from configured repositories. It does not itself upgrade the installed applications.

Search for and inspect software

apt search nginx — search package names and descriptions.

apt show nginx — display package details.

apt list --installed — list installed packages.

Install and remove a package

sudo apt install nginx — install Nginx and required dependencies.

sudo apt remove nginx — remove the package but generally leave system configuration files.

sudo apt purge nginx — remove the package and its package-managed system configuration files.

sudo apt autoremove — offer to remove automatically installed packages that are no longer required.

Review the list of packages APT proposes to install or remove before accepting. Purging configuration can remove settings you may want to keep.

Upgrade installed packages

sudo apt upgrade — upgrade installed packages where the operation does not require removing packages.

sudo apt full-upgrade — perform a broader upgrade that may install or remove packages to complete dependency changes.

On a server, plan upgrades and review the proposed changes rather than running them automatically without checking impact.

5. DNF on Fedora and Red Hat-Based Systems

DNF is the package manager used by current Fedora and many modern Red Hat-based distributions. Some older enterprise systems use YUM or provide a compatible yum command.

Search and inspect packages

dnf search nginx — search available packages.

dnf info nginx — inspect package information.

dnf list installed — list installed packages.

dnf repolist — display enabled repositories.

Install and remove software

sudo dnf install nginx — install a package and resolve dependencies.

sudo dnf remove nginx — remove the package.

sudo dnf autoremove — remove packages that were installed as dependencies and are no longer needed, where supported.

Update the system

sudo dnf check-update — check whether updates are available. Some versions return a non-zero status when updates are found; this is not necessarily an error.

sudo dnf upgrade — apply available package updates.

sudo dnf history — review package transaction history.

DNF normally shows a transaction summary before making changes. Check which packages will be installed, upgraded or removed before confirming.

6. Understanding dpkg and RPM

dpkg and rpm are lower-level package tools. They are useful for inspecting installed packages and working with local package files, but they do not provide the same repository-based dependency resolution as APT or DNF.

Debian package tool: dpkg

dpkg -l — list package records.

dpkg -s nginx — inspect an installed package.

dpkg -L nginx — list files installed by a package.

sudo dpkg -i ./example.deb — install a local Debian package file.

If a local package installation reports missing dependencies, use APT to resolve them where appropriate, for example sudo apt --fix-broken install. Review the proposed changes before proceeding.

RPM package tool

rpm -qa — list installed RPM packages.

rpm -qi nginx — display information about an installed package.

rpm -ql nginx — list files belonging to an installed package.

rpm -qf /usr/bin/ssh — identify the package that owns a file, if it is package-managed.

sudo rpm -Uvh ./example.rpm — install or upgrade a local RPM package file.

For ordinary software installation on an RPM-based system, prefer DNF because it can resolve dependencies from configured repositories.

7. Updates, Maintenance and Package Verification

Package maintenance is more than installing new software. Administrators should understand what is installed, where it came from and whether an update may affect a service.

  • Inventory: use apt list --installed, dnf list installed, dpkg -l or rpm -qa to review installed software.
  • Repository review: inspect configured sources and disable repositories that are no longer trusted or required.
  • Change planning: check release notes and compatibility before major version upgrades.
  • Backups: back up important configuration and data before changes that could affect a service.
  • Service checks: after updating a server package, verify the related service and application.

Package verification commands can help identify changes to files managed by a package. For example, rpm -V package-name checks installed files against RPM metadata. Verification output must be interpreted carefully: a reported difference is a clue to investigate, not automatically proof of compromise.

8. Common Package Management Problems

ProblemWhat to check
Package cannot be foundCheck the package name, repository configuration and refreshed package metadata.
Repository is unreachableCheck network connectivity, DNS resolution, proxy settings and repository status.
Dependency conflictRead the package manager's transaction details; avoid forcing incompatible versions.
Another package operation is runningWait for the active package operation to finish. Do not delete lock files or terminate package processes blindly.
Insufficient disk spaceCheck available space with df -h and investigate package caches or logs carefully.
Service fails after an updateCheck service status and logs, review configuration changes and consult release notes.

Useful diagnostic commands include df -h for filesystem space, systemctl status service-name for a service and journalctl -u service-name for its systemd journal entries.

Lab questions

10. Security Best Practices

  • Use official distribution repositories or repositories from vendors you explicitly trust.
  • Do not disable package signature verification to make an installation succeed.
  • Avoid piping unknown internet scripts directly into a root shell.
  • Read proposed install, upgrade and removal transactions before confirming.
  • Keep production systems updated through a planned maintenance process.
  • Back up important data and configuration before major package changes.
  • Use the distribution's package manager instead of manually replacing system-managed files.

11. Frequently Asked Questions

Is APT the same as dpkg?

No. APT is a higher-level package manager that works with repositories and resolves dependencies. dpkg works directly with Debian package files and the local package database.

Are DNF and YUM the same?

They are related tools in the Red Hat package-management ecosystem. DNF is the modern successor to YUM, and some systems provide a yum command for compatibility.

Does apt update upgrade my software?

No. apt update refreshes package metadata. Use an upgrade command to apply available updates.

Should I download a .deb or .rpm file from any website?

No. Prefer trusted distribution repositories or official vendor sources, and verify package authenticity and compatibility before installation.

Which package manager should I learn first?

Learn the package manager used by your current distribution, then understand the equivalent workflow in the other major family. Network and Linux administrators commonly encounter both.
