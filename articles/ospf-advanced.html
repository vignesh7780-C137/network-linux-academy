Advanced OSPF Explained: Areas, LSAs, DR and BDR

OSPF (Open Shortest Path First) is a link-state dynamic routing protocol used to exchange routing information within an autonomous system.

In the introductory OSPF article, we explored the basic operation and configuration of OSPF. This article goes deeper into its architecture, database, packet exchange process and advanced configuration.

1. Understanding OSPF Areas

OSPF divides a large routing domain into smaller logical sections called areas. This hierarchical design helps reduce routing overhead and limits the amount of topology information that routers need to process.

Each OSPF area maintains its own link-state database. Routers within an area exchange topology information so that they can calculate routes using the SPF algorithm.

Area 0 — Backbone Area

Area 0 is the backbone area of an OSPF network. Other regular OSPF areas are expected to connect to Area 0, either directly or through a properly configured virtual link.

Routers that connect multiple areas are called Area Border Routers (ABRs).

Common OSPF Router Types

Router Type Description
Internal Router All OSPF interfaces belong to the same area.
Backbone Router Has at least one interface in Area 0.
ABR Connects multiple OSPF areas.
ASBR Redistributes routes from another routing domain into OSPF.

2. Link-State Advertisements (LSAs)

LSAs are information structures used by OSPF routers to describe network topology and routing information.

Routers exchange LSAs and use them to build their link-state databases.

Important LSA Types

LSA Type Name Purpose
Type 1 Router LSA Describes a router's links within an area.
Type 2 Network LSA Describes routers connected to a multi-access network; generated by the DR.
Type 3 Summary LSA Advertises inter-area network information through an ABR.
Type 4 ASBR Summary LSA Provides information about how to reach an ASBR.
Type 5 External LSA Advertises external routes redistributed into OSPF.
Type 7 NSSA External LSA Advertises external routes within a Not-So-Stubby Area.

Different LSA types have different flooding scopes and purposes. Not every LSA is flooded throughout the entire OSPF routing domain.

3. Link-State Database (LSDB)

The LSDB is the database containing the link-state information collected by OSPF routers.

Routers within the same area should have synchronized link-state databases for that area.

The LSDB provides the topology information required by OSPF to calculate the shortest paths.

Verification command:

show ip ospf database

4. SPF Algorithm — Dijkstra

OSPF uses the Shortest Path First (SPF) algorithm, developed by Edsger Dijkstra, to calculate the best paths through a network topology.

The basic process is:

  1. Collect link-state information from neighboring routers.
  2. Build and synchronize the LSDB.
  3. Run the SPF calculation.
  4. Determine the lowest-cost paths.
  5. Install selected routes in the routing table.

OSPF generally calculates route cost using interface cost. Cisco's default reference bandwidth and interface bandwidth affect the default cost calculation. 

Router# show ip ospf interface

5. DR and BDR Elections

On broadcast multi-access networks, such as Ethernet LANs, OSPF elects a Designated Router (DR) and a Backup Designated Router (BDR).

These roles reduce the number of OSPF adjacencies and simplify the exchange of link-state information on shared networks.

Designated Router (DR)

The DR acts as the central point for certain OSPF database exchanges on the multi-access segment.

Backup Designated Router (BDR)

The BDR monitors the DR and takes over its role if the DR becomes unavailable.

Election Rules

  1. The router with the highest OSPF interface priority wins.
  2. If priorities are equal, the highest Router ID wins.
  3. An interface priority of 0 makes a router ineligible for DR or BDR election.

DR and BDR elections are non-preemptive by default. A newly introduced router with a higher priority does not automatically replace an existing DR.

6. OSPF Neighbor States

OSPF routers pass through several states while establishing neighbor relationships and synchronizing databases.

State Meaning
Down No Hello packet has been received from the neighbor.
Attempt Used in NBMA environments when attempting to contact a neighbor.
Init A Hello packet has been received, but bidirectional communication is not confirmed.
2-Way Bidirectional Hello communication is established.
ExStart Routers negotiate master/slave roles and initial database exchange sequence numbers.
Exchange Database Description packets are exchanged.
Loading Additional link-state information is requested and received.
Full Adjacent routers have synchronized their databases.
Important: On broadcast networks, DROTHER routers can remain in the 2-Way state with one another. They normally form full adjacencies with the DR and BDR.

7. Configuring Multi-Area OSPF

Consider a network with three routers. R1 and R2 belong to Area 0, while R3 connects to Area 1 through R2. 


R1 -------- R2 -------- R3

       Area 0       Area 1

R1 LAN: 192.168.1.0/24
R3 LAN: 192.168.3.0/24

R1-R2: 10.0.12.0/30
R2-R3: 10.0.23.0/30

R1 Configuration

enable
configure terminal

router ospf 1
 router-id 1.1.1.1
 network 192.168.1.0 0.0.0.255 area 0
 network 10.0.12.0 0.0.0.3 area 0

end
write memory

R2 Configuration

enable
configure terminal

router ospf 1
 router-id 2.2.2.2
 network 10.0.12.0 0.0.0.3 area 0
 network 10.0.23.0 0.0.0.3 area 1

end
write memory

R3 Configuration

enable
configure terminal

router ospf 1
 router-id 3.3.3.3
 network 192.168.3.0 0.0.0.255 area 1
 network 10.0.23.0 0.0.0.3 area 1

end
write memory

R2 is the ABR because it connects Area 0 and Area 1. The router IDs above are explicitly configured identifiers; they are not necessarily interface IP addresses.

8. OSPF Verification Commands

show ip ospf
show ip ospf neighbor
show ip ospf database
show ip ospf interface
show ip route ospf
show ip protocols

These commands help inspect OSPF processes, neighbor states, LSAs, interface parameters and learned routes.

9. OSPF Troubleshooting

Problem Possible Cause
Neighbors stuck in Init One-way Hello communication or network filtering.
Neighbors stuck in ExStart/Exchange Possible MTU mismatch or database exchange issue.
No neighbor relationship Area mismatch, Hello/dead timer mismatch, authentication or interface issues.
Missing routes Incorrect network statements, area configuration or filtering.
Unexpected DR election Interface priority or Router ID selection.

10. Practical Packet Tracer Lab

Build a multi-area OSPF network using three routers.

  1. Connect R1, R2 and R3 in a line.
  2. Configure the IP addresses on all interfaces.
  3. Place the R1-R2 link in Area 0.
  4. Place the R2-R3 link in Area 1.
  5. Configure the LAN behind R1 in Area 0.
  6. Configure the LAN behind R3 in Area 1.
  7. Configure R2 as an ABR.
  8. Verify neighbor relationships and OSPF routes.
  9. Ping between the end devices.
  10. Inspect the OSPF database and identify the LSAs.

11. Key Takeaways

  • OSPF uses a hierarchical area architecture.
  • Area 0 is the backbone area.
  • LSAs carry topology and routing information.
  • The LSDB stores link-state information.
  • Dijkstra's SPF algorithm calculates shortest paths.
  • DR and BDR reduce adjacency overhead on multi-access networks.
  • OSPF neighbors progress through multiple states.
  • ABRs connect OSPF areas.

Conclusion

Understanding advanced OSPF concepts is essential for designing, configuring and troubleshooting larger enterprise networks. Areas, LSAs, LSDB synchronization and SPF calculations explain how OSPF maintains accurate routing information across a network.
