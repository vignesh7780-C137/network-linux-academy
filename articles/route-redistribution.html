Route Redistribution Explained

Route redistribution is the process of exchanging routing information between different routing protocols or routing processes.

In enterprise networks, an organization may use OSPF in one part of its infrastructure and EIGRP in another. Redistribution allows routes learned by one protocol to be introduced into another routing protocol.

1. What Is Route Redistribution?

Different routing protocols maintain their own routing information and use different algorithms and metrics. Redistribution allows a router to take routes learned from one routing source and advertise them into another.

For example:


       OSPF DOMAIN
            |
            |
           R1
            |
       REDISTRIBUTION
          ROUTER
            |
           R2
            |
       EIGRP DOMAIN

R1 and R2 can be connected through a router that participates in both routing domains. That router can redistribute routes between OSPF and EIGRP.

2. Why Is Redistribution Needed?

Common situations include:

  • Connecting networks that use different routing protocols.
  • Merging two organizations with different network designs.
  • Transitioning from one routing protocol to another.
  • Connecting enterprise networks to external routing domains.
  • Integrating legacy infrastructure with newer networks.

3. One-Way vs Mutual Redistribution

One-Way Redistribution

Routes are redistributed in only one direction. For example, OSPF routes may be advertised into EIGRP without redistributing EIGRP routes back into OSPF.

Mutual Redistribution

Routes are redistributed in both directions. OSPF routes enter EIGRP, and EIGRP routes enter OSPF. 


       OSPF  ---------->  EIGRP
             One-way

       OSPF  <----------> EIGRP
             Mutual

Mutual redistribution requires careful planning because routes can potentially be advertised back into their original routing protocol.

4. Understanding Seed Metrics

Different routing protocols use different metric systems. A route redistributed into another protocol may need a suitable metric before the receiving protocol can use it.

Examples of routing metrics:

Protocol Metric Characteristics
RIP Hop count
OSPF Cost
EIGRP Composite metric, primarily bandwidth and delay by default
BGP Path attributes and policy-based selection

A seed metric is an initial metric assigned to a redistributed route when the destination protocol requires one.

Important: Never assume that a route's original metric can be copied directly into another routing protocol. Metric conversion and configuration must be planned.

5. Administrative Distance

Administrative Distance (AD) indicates the trustworthiness of a routing information source on Cisco routers.

When multiple routing sources provide a route to the same destination prefix, the router generally prefers the route with the lowest administrative distance.

Routing Source Default AD
Connected0
Static1
EIGRP Summary5
eBGP20
EIGRP Internal90
OSPF110
IS-IS115
RIP120
EIGRP External170
iBGP200

Administrative distance is a local router preference and is not advertised to other routers as a routing protocol metric.

6. Redistribution Between OSPF and EIGRP

Consider a router running both OSPF and EIGRP. It connects two routing domains and redistributes routes between them. 


       OSPF DOMAIN
      192.168.1.0/24
             |
             |
             R1
       OSPF + EIGRP
             |
             |
             R2
             |
       EIGRP DOMAIN
      192.168.2.0/24

The redistribution router must participate in both routing processes and have working interfaces and routing information.

7. Cisco Configuration Example

The following examples use classic Cisco IOS routing configuration. They assume that interface addressing and routing processes have already been configured.

Configure OSPF

router ospf 1
 network 10.0.12.0 0.0.0.3 area 0
 network 192.168.1.0 0.0.0.255 area 0

Configure EIGRP

router eigrp 100
 network 10.0.23.0 0.0.0.3
 network 192.168.2.0 0.0.0.255
 no auto-summary

Redistribute OSPF into EIGRP

router eigrp 100
 redistribute ospf 1 metric 10000 100 255 1 1500

The EIGRP metric values represent bandwidth in Kbps, delay in tens of microseconds, reliability, load and MTU. The example uses a seed metric suitable for a basic lab.

Redistribute EIGRP into OSPF

router ospf 1
 redistribute eigrp 100 subnets

The subnets keyword allows eligible subnet routes to be redistributed. Exact command support can vary by IOS version.

8. Routing Loops and Route Feedback

One of the most important risks of mutual redistribution is route feedback.

Consider this sequence:

  1. OSPF advertises a route into EIGRP.
  2. EIGRP advertises the route to another router.
  3. The route is redistributed back into OSPF.
  4. Routers may now learn the same destination through an unintended routing path.

Poorly designed redistribution can cause routing loops, suboptimal paths and unstable routing decisions.

9. Preventing Redistribution Problems

Common techniques include:

  • Route tagging.
  • Route maps.
  • Prefix lists.
  • Distribute lists where appropriate.
  • Carefully planned redistribution boundaries.
  • Explicit metric configuration.

Example: Route Tagging with OSPF

route-map EIGRP-TO-OSPF permit 10
 set tag 100

router ospf 1
 redistribute eigrp 100 subnets route-map EIGRP-TO-OSPF

The route map tags eligible redistributed routes with tag 100. A corresponding filtering policy can prevent those routes from being redistributed back into EIGRP.

10. Verification Commands

show ip route
show ip protocols
show ip ospf database
show ip eigrp topology
show running-config
show route-map

Use these commands to inspect routing tables, routing processes, protocol databases and redistribution policies.

11. Common Troubleshooting Issues

Problem Possible Cause
Routes not redistributed Incorrect source process, route map or redistribution command.
EIGRP routes missing Missing or invalid EIGRP seed metric.
OSPF routes missing Missing redistribution configuration or route filtering.
Unexpected routing paths Administrative distance, metrics or route policies.
Routing loops Route feedback caused by mutual redistribution.

12. Practical Packet Tracer Lab

Build a network with three routers:

  • R1 runs OSPF.
  • R2 runs both OSPF and EIGRP.
  • R3 runs EIGRP.

Lab tasks:

  1. Configure IP addresses on all interfaces.
  2. Configure OSPF between R1 and R2.
  3. Configure EIGRP between R2 and R3.
  4. Verify that both routing protocols form the expected adjacencies.
  5. Redistribute OSPF into EIGRP.
  6. Verify that R3 learns the OSPF LAN prefix.
  7. Redistribute EIGRP into OSPF.
  8. Verify that R1 learns the EIGRP LAN prefix.
  9. Test end-to-end connectivity.
  10. Experiment with route maps and route tags.

13. Key Takeaways

  • Redistribution exchanges routes between routing protocols.
  • One-way redistribution works in one direction.
  • Mutual redistribution works in both directions.
  • Seed metrics may be required by the destination protocol.
  • Administrative distance influences local route selection.
  • Route tagging and filtering help prevent route feedback.
  • Careful planning is essential in enterprise networks.

Conclusion

Route redistribution is an essential concept in complex enterprise network environments. Understanding metrics, administrative distance, route feedback and filtering provides the foundation for safely connecting different routing domains.
