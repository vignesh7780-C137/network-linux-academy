1. Understanding Routing

Before learning OSPF, it is important to understand what routing means in computer networking.

Routing is the process of selecting a path through which network packets travel from a source network to a destination network. Routers use routing information to decide where to forward packets.

A router maintains a routing table containing information about destination networks and the paths available to reach them.

Source network
↓
Router examines routing table
↓
Selects the best matching route
↓
Forwards packet to next hop
↓
Destination network

Routing is essential because devices on different IP networks cannot communicate directly at Layer 2. They generally rely on routers or Layer 3 switches to forward traffic between networks.

2. Static Routing vs. Dynamic Routing

There are different ways to populate a router's routing table. Two fundamental approaches are static routing and dynamic routing.

Static routing

Static routing requires an administrator to manually configure routes. The router does not automatically discover alternative paths through a routing protocol.

Example Cisco IOS command:

ip route 192.168.20.0 255.255.255.0 10.0.12.2

This command tells the router to reach network 192.168.20.0/24 through next-hop address 10.0.12.2.

Dynamic routing

Dynamic routing protocols allow routers to exchange routing information automatically. They can learn remote networks and update routes when network topology changes.

Feature Static routing Dynamic routing
Configuration Manual Protocol-based
Route discovery Administrator configures routes Routers exchange information
Topology changes May require manual updates Can adapt automatically
Resource usage Generally low Uses CPU, memory and bandwidth
Typical use Small or predictable networks Networks with multiple routers and paths

Common dynamic routing protocols include RIP, OSPF, EIGRP and BGP. Each uses different mechanisms and metrics to exchange and select routing information.

3. What Is OSPF?

OSPF (Open Shortest Path First) is a link-state interior gateway routing protocol used to exchange routing information within an autonomous system.

OSPF allows routers to learn about network topology, build a link-state database, and calculate the best paths to destination networks.

It uses the Shortest Path First (SPF) algorithm, also known as Dijkstra's algorithm, to calculate paths based on OSPF cost.

In simple terms

OSPF enables routers to share information about the networks and links they know. Each router uses this information to calculate its own best routes.

OSPF is an open standard, which means it is not limited to a single router manufacturer. It is commonly used in enterprise networks.

4. OSPFv2 and OSPFv3

OSPF has different versions designed to support different IP protocol environments.

Version Primary use Specification
OSPFv2 IPv4 routing RFC 2328
OSPFv3 Originally developed for IPv6 RFC 5340

OSPFv3 was originally specified for IPv6. Later extensions also support address families such as IPv4. The configuration and operational details can vary across platforms.

In this tutorial, all examples use OSPFv2 with IPv4.

5. Important Characteristics of OSPF

  • Link-state protocol: Routers exchange information about their links and network topology.
  • Open standard: Supported by multiple networking vendors.
  • Classless routing: Supports variable-length subnet masks and CIDR prefixes.
  • Hierarchical design: Supports dividing an OSPF domain into areas.
  • Metric: Uses cost to select preferred paths.
  • Fast adaptation: Detects topology changes and recalculates routes.
  • Multicast communication: Uses multicast addresses for many OSPF control messages on applicable network types.
  • Equal-cost multipath: Can install multiple equal-cost paths when supported and configured.

6. Core OSPF Components

Several important components work together to make OSPF function.

6.1 Router ID

A Router ID (RID) is a 32-bit identifier used to identify an OSPF router within the OSPF routing domain. It is written in dotted-decimal format.

Example:

1.1.1.1

An administrator can manually configure a Router ID. If one is not configured, the router selects one according to platform-specific selection rules. On Cisco IOS, these rules commonly consider loopback and active physical interface addresses.

Router IDs should be unique within the OSPF domain.

6.2 Neighbor table

The neighbor table contains information about other OSPF routers discovered on connected network segments.

6.3 Link-State Database (LSDB)

The LSDB stores the link-state information used by OSPF routers to understand the topology of their area. Routers in the same area should have synchronized link-state databases.

6.4 Routing table

After running the SPF calculation, the router installs selected routes into its IP routing table, subject to route selection and platform rules.

Neighbor information
↓
Link-State Database
↓
SPF calculation
↓
OSPF routes
↓
IP routing table

These databases have different purposes. The neighbor table tracks router relationships, the LSDB describes topology, and the routing table contains selected forwarding routes.

7. OSPF Neighbors and Adjacency

OSPF routers use Hello packets to discover other OSPF-speaking routers on a connected network segment. These discovered routers can become OSPF neighbors.

A neighbor relationship allows routers to communicate and, where required by the network type, establish an adjacency to synchronize link-state information.

Neighbor vs. adjacency

A neighbor is an OSPF router discovered on a shared network. An adjacency is a more advanced relationship in which routers synchronize their link-state databases. Not every neighbor on every network type must become fully adjacent to every other neighbor.

Important neighbor parameters

Common settings that must be compatible for routers to form a neighbor relationship include:

  • Area ID
  • Hello interval
  • Dead interval
  • Authentication settings, where configured
  • Compatible network type and other required parameters
  • Matching IP subnet on conventional shared networks

A mismatch in important parameters can prevent routers from establishing the expected relationship.

8. OSPF Neighbor States

OSPF uses a series of states while discovering neighbors and forming adjacencies.

1. Down

No Hello packets have been received from the neighbor within the relevant process state.

2. Init

A Hello packet has been received, but bidirectional communication has not yet been confirmed.

3. 2-Way

Bidirectional Hello communication has been established.

4. ExStart

Routers begin negotiating the master-slave relationship and initial database exchange sequence.

5. Exchange

Routers exchange Database Description packets containing summaries of their link-state databases.

6. Loading

Routers request and receive missing or newer link-state information.

7. Full

The required link-state databases have been synchronized and the adjacency is complete.

On broadcast networks, routers that are not selected as the Designated Router or Backup Designated Router may remain in the 2-Way state with one another. This can be normal behavior.

9. OSPF Areas

OSPF supports a hierarchical network design using areas. An area is a logical grouping of OSPF interfaces and routers that share area-specific link-state information.

Dividing a large network into areas can limit the scope of topology information and reduce the processing required by routers.

Area 0 — Backbone area

Area 0 is the backbone area of a conventional multiarea OSPF design. Other regular areas connect to the backbone through Area Border Routers (ABRs).

Area 1 Branch network
Area 0 Backbone
Area 2 Another branch

Types of OSPF routers

  • Internal Router: Has all OSPF interfaces in the same area.
  • Backbone Router: Has at least one OSPF interface in Area 0.
  • Area Border Router (ABR): Connects Area 0 to one or more other areas.
  • Autonomous System Boundary Router (ASBR): Introduces external routing information into OSPF.

Single-area OSPF is often used in smaller networks. Multiarea OSPF becomes useful when a larger network needs a more structured design.

10. OSPF Packet Types

OSPFv2 uses five packet types to establish relationships and exchange link-state information.

Packet type Name Purpose
Type 1 Hello Discovers and maintains neighbor relationships.
Type 2 Database Description (DBD) Summarizes link-state database information.
Type 3 Link-State Request (LSR) Requests specific link-state information.
Type 4 Link-State Update (LSU) Transports link-state advertisements.
Type 5 Link-State Acknowledgment (LSAck) Acknowledges received link-state advertisements.

These packets work together during neighbor discovery, database synchronization, and ongoing topology updates.

11. LSAs and the Link-State Database

A Link-State Advertisement (LSA) is a data structure that describes topology or routing information within OSPF.

Routers distribute LSAs through the OSPF domain according to their type and flooding scope. The received information is stored in the Link-State Database.

Common OSPFv2 LSA types

LSA type Name General purpose
Type 1 Router LSA Describes a router's links within an area.
Type 2 Network LSA Describes a multi-access network and its attached routers.
Type 3 Summary LSA Advertises inter-area network information.
Type 4 ASBR Summary LSA Describes how to reach an ASBR.
Type 5 AS External LSA Advertises routes external to the OSPF domain.
Type 7 NSSA External LSA Advertises external routes within an NSSA.

This is an introductory list of commonly encountered LSA types. OSPF has additional LSA types and rules for different network designs.

12. OSPF Cost and the SPF Algorithm

OSPF uses a metric called cost to evaluate paths. Lower total cost is preferred when comparing eligible paths to a destination.

How is OSPF cost calculated?

On Cisco IOS, the traditional default cost calculation is based on interface bandwidth and a reference bandwidth.

Interface Cost = Reference Bandwidth / Interface Bandwidth

With the traditional Cisco default reference bandwidth of 100 Mbps, a Fast Ethernet interface with a bandwidth of 100 Mbps has a cost of 1. A Gigabit Ethernet interface may also have a cost of 1 unless the reference bandwidth is adjusted.

For this reason, administrators often configure a consistent reference bandwidth across OSPF routers so that higher-speed interfaces can be distinguished.

What is the SPF algorithm?

OSPF uses Dijkstra's Shortest Path First algorithm to calculate the shortest paths from the local router to destinations represented in its LSDB.

The algorithm evaluates the topology and accumulates link costs to determine the best paths.

Example path comparison

Path A: Router 1 → Router 2 → Router 4

Cost: 10 + 10 = 20

Path B: Router 1 → Router 3 → Router 4

Cost: 5 + 30 = 35

Preferred path: Path A (total cost 20)

The example illustrates the basic principle: when the paths are otherwise eligible, OSPF prefers the path with the lower total cost.

13. How OSPF Works Step by Step

The following sequence provides a simplified view of OSPF operation:

  1. Neighbor discovery

    Routers send and receive Hello packets on OSPF-enabled interfaces.

  2. Neighbor relationship

    Compatible routers establish neighbor relationships.

  3. Adjacency and database exchange

    Routers that need to become adjacent exchange database summaries and synchronize LSAs.

  4. LSDB synchronization

    Routers build a consistent view of the topology within their area.

  5. SPF calculation

    Each router calculates its best paths using its own position in the topology.

  6. Route installation

    Selected OSPF routes are installed into the IP routing table.

  7. Topology change

    When a relevant link or route changes, OSPF distributes updated information and recalculates paths as necessary.

14. Practical Cisco OSPF Lab

Now let's configure OSPF on two Cisco routers. This simple lab demonstrates how routers can automatically learn remote networks without manually configuring static routes.

Lab objective

Establish an OSPF neighbor relationship between R1 and R2. Advertise their respective LAN networks so that devices on both LANs can communicate through the routers.

Topology

LAN 1 192.168.10.0/24 PC1
R1 10.0.12.1/30
10.0.12.0/30 ────────────
R2 10.0.12.2/30
LAN 2 192.168.20.0/24 PC2

The diagram is a logical representation. In Packet Tracer, connect the routers using an Ethernet link and connect each router's LAN interface to a switch and PC.

IP addressing plan

Device Interface IP address Subnet mask
R1G0/010.0.12.1255.255.255.252
R1G0/1192.168.10.1255.255.255.0
R2G0/010.0.12.2255.255.255.252
R2G0/1192.168.20.1255.255.255.0
PC1NIC192.168.10.10255.255.255.0
PC2NIC192.168.20.10255.255.255.0

Configure PC1's default gateway as 192.168.10.1 and PC2's default gateway as 192.168.20.1.

Step 1: Configure R1 interfaces

enable configure terminal hostname R1 interface gigabitEthernet 0/0 ip address 10.0.12.1 255.255.255.252 no shutdown exit interface gigabitEthernet 0/1 ip address 192.168.10.1 255.255.255.0 no shutdown exit

Step 2: Configure R2 interfaces

enable configure terminal hostname R2 interface gigabitEthernet 0/0 ip address 10.0.12.2 255.255.255.252 no shutdown exit interface gigabitEthernet 0/1 ip address 192.168.20.1 255.255.255.0 no shutdown exit

Step 3: Configure OSPF on R1

router ospf 1 router-id 1.1.1.1 network 10.0.12.0 0.0.0.3 area 0 network 192.168.10.0 0.0.0.255 area 0 passive-interface gigabitEthernet 0/1 end

Step 4: Configure OSPF on R2

router ospf 1 router-id 2.2.2.2 network 10.0.12.0 0.0.0.3 area 0 network 192.168.20.0 0.0.0.255 area 0 passive-interface gigabitEthernet 0/1 end

The OSPF process ID is locally significant on Cisco IOS. It does not need to match between routers. Both routers use Area 0 on their shared link, allowing them to establish an OSPF neighbor relationship.

The wildcard mask is the inverse of the subnet mask. For example, 255.255.255.252 corresponds to 0.0.0.3.

The passive-interface command prevents OSPF Hello packets from being sent through the LAN interface where no OSPF neighbor is expected. The LAN network is still advertised into OSPF.

Step 5: Verify the neighbor relationship

On either router, run:

show ip ospf neighbor

You should see the other router's Router ID and a neighbor state indicating a successful adjacency. On this point-to-point-style Ethernet connection, the expected state is Full.

Step 6: Verify learned routes

show ip route ospf

R1 should learn the 192.168.20.0/24 network through R2. R2 should learn the 192.168.10.0/24 network through R1.

Step 7: Test connectivity

From PC1, open the command prompt and run:

ping 192.168.20.10

If the addressing, default gateways, interfaces, and OSPF configuration are correct, PC1 should be able to reach PC2.

Lab success criteria
  • Both router interfaces are up/up.
  • R1 and R2 form an OSPF adjacency.
  • R1 learns the remote LAN route.
  • R2 learns the remote LAN route.
  • PC1 can ping PC2.

16. Troubleshooting Common OSPF Problems

Problem 1: OSPF neighbors are not forming

Possible causes:

  • Incorrect IP address or subnet mask.
  • Interfaces are administratively down.
  • Area IDs do not match.
  • Hello or dead intervals are incompatible.
  • Authentication settings do not match.
  • OSPF is not enabled on the expected interface.

Useful commands:

show ip interface brief show ip ospf interface show ip ospf neighbor

Problem 2: Neighbor stuck in 2-Way state

On a broadcast network, this can be normal between routers that are not the DR or BDR. On other network types or topologies, investigate the expected adjacency behavior and network type.

Problem 3: Neighbor stuck in ExStart or Exchange

Possible causes include MTU mismatches, duplicate Router IDs, or problems during database exchange. Check interface MTU and OSPF neighbor information.

Problem 4: OSPF adjacency is Full, but the route is missing

Check whether the destination network is actually advertised, whether the relevant interface is participating in OSPF, and whether route filtering, area design, or route selection affects the result.

Problem 5: OSPF chooses an unexpected path

Inspect interface costs, reference bandwidth, topology information, and the routing table. A lower total OSPF cost is preferred among eligible paths.

17. Frequently Asked Questions

1. Is OSPF a distance-vector or link-state protocol?

OSPF is a link-state routing protocol. Routers exchange link-state information and calculate routes using the SPF algorithm.

2. What algorithm does OSPF use?

OSPF uses Dijkstra's Shortest Path First algorithm to calculate best paths based on link-state information and cost.

3. What is the default OSPF administrative distance on Cisco IOS?

The commonly used Cisco IOS default administrative distance for OSPF is 110. This value is configurable and can differ on other platforms.

4. Does the OSPF process ID need to match?

No. On Cisco IOS, the OSPF process ID is locally significant. Neighboring routers do not need to use the same process ID.

5. What is Area 0?

Area 0 is the OSPF backbone area. In a conventional multiarea design, other regular areas connect to the backbone.

6. What is a Router ID?

A Router ID is a 32-bit identifier used to identify an OSPF router. It is written in dotted-decimal format.

7. What is the difference between OSPFv2 and OSPFv3?

OSPFv2 is used for IPv4 routing. OSPFv3 was originally designed for IPv6 and has extensions for additional address families.

8. What does a Full neighbor state mean?

It indicates that the required link-state databases have been synchronized between the adjacent routers.

18. Conclusion

OSPF is an important dynamic routing protocol used in enterprise and service-provider networks. Understanding how it discovers neighbors, exchanges link-state information, builds an LSDB, and calculates paths provides a strong foundation for routing and switching.

Reading about OSPF is only the first step. Practise configuring it in Packet Tracer, inspect neighbor relationships, examine routing tables, and deliberately introduce configuration mistakes to understand troubleshooting.
